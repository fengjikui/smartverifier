# Windows 一键更新

适用于已经用 Git 安装、分支为 `main`、已有正品数据的 Windows 电脑。需要已有 Node.js 24、Git 和本机 Python 虚拟环境；不是首次安装脚本。不会清空业务库、重建管理员或启动真实模型。

## 怎么用

1. 等检测、导入结束，在业务服务终端按 `Ctrl+C` 正常停止服务；托管的服务也要先停止。
2. 第一次先按[手工更新说明](部署说明.md#windows-update)完成备份，再在原项目目录执行一次 `git pull --ff-only origin main`，取得本更新脚本。若有本地代码修改，先保留处理，不强制覆盖；后续双击时由脚本自动备份。
3. **双击项目根目录的 `update-windows.cmd`**。也可在 PowerShell 中运行：

   ```powershell
   .\update-windows.cmd
   ```

4. 等待窗口显示“更新完成”，再按原方式启动：真实识别用 `npm run start:real`，仅资料维护沿用 `npm start`。用原账号登录，核对正品数量与图片。

后续只需重复停止服务、双击更新、按原方式启动。无需激活虚拟环境，也无需改变 PowerShell 执行策略。默认不会自动重启，避免更新失败后误启动不完整的版本。

## 自动做哪些事情

依次执行，任一步失败就停止：

1. 检查 Node、Git、Python 虚拟环境、`main` 分支和本地代码状态；检查原库与配置账号文件是否存在、服务端口和进程锁是否空闲。不结束已有业务进程。
2. 备份 `.env.local`、整个 `var/`、`SV_STATE_DIR` 指定的额外数据目录、`SV_ADMIN_USERS_FILE` 指定的额外账号文件；系统环境变量优先于 `.env.local`。目录重叠时只备份一次。只排除进程互斥锁。
3. 原图、SQLite、存在的 WAL/SHM、管理员配置等逐文件计算 SHA-256，与副本核对。**备份完成并校验成功后才获取和更新远端代码**。
4. 获取 `origin/main`，只允许快进更新。发现本地改动、历史分叉或目标版本会覆盖私有数据／配置时停止，不执行 `reset` 或 `clean`。
5. 仅当 Windows 配置仍使用旧 macOS 默认 `.venv/bin/python` 时，调整为 Windows 路径；原配置已备份，其余模型、账号、数据路径等设置保留。终端／系统环境变量中的错误路径需要先修正，脚本不修改系统环境变量。
6. 用 `npm ci --include=dev --no-audit --no-fund` 安装 Node 依赖，在选定虚拟环境内用 pip 安装 `requirements.txt`。缺少 pip 时尝试用 Python 自带的 `ensurepip` 离线补齐，不安装到系统 Python。
7. 运行类型检查和前端构建，再校验受保护的原始资料未被改写，记录完成状态。不会重新录入正品、初始化账号或自动提交 MES。

更新期间，同一项目／数据目录不能再次更新，新版业务启动入口也会拒绝在更新锁存在时启动。正常退出会释放自己的锁；进程异常退出后，确认原 PID 已不存在才回收遗留锁，不结束不明进程。

## 备份和报错信息在哪里

默认在**项目旁的同名备份目录**中，每次新建独立时间目录，不覆盖或自动删除上次备份。例如：

```text
D:/smartverifier-backups/日期-唯一编号/
  update.log            # UTF-8 阶段日志及依赖命令输出，常见凭证已脱敏
  result.json           # 成功／失败、失败阶段、退出码、代码版本、环境和时间
  private-backup/       # 私有资料：原图、数据库、配置和账号哈希
    manifest.json       # 原位置、备份路径、文件大小与 SHA-256
    ...
```

窗口会显示实际路径。**排错时发送 `update.log` 和 `result.json`，不要发送 `private-backup`**；发送前仍应快速检查日志是否含公司敏感信息。备份包含管理员凭证哈希、模型配置与原图，应保存在仅部署人员可访问的位置。

预检初始化失败、还无法创建常规记录时，会尽量在 Windows 临时目录中生成 `jianwei-update-error-...` 诊断目录，并显示位置。日志记录备份是否完整；失败运行中的不完整备份不能当作恢复依据。

失败后，已完成的更新步骤不会自动撤销，**不会继续构建或启动服务，也不会自动把旧备份覆盖回当前资料**。根据日志修复网络、依赖或配置问题后可重新运行；要回退时先保留当前状态，再按[部署说明](部署说明.md#windows-update)使用旧提交和匹配的完整备份副本核验。

## 可选操作

只检查条件，不拉取、备份、安装或构建（仍会产生诊断记录，并短暂取得／释放更新锁）：

```powershell
.\update-windows.cmd --check
```

指定其他独立备份位置，不能放在项目或原数据目录内部：

```powershell
.\update-windows.cmd --backup-dir "D:/鉴微备份"
```

Node、pip 依赖安装需要访问相应包源，Git 需要访问配置的远端；本脚本不会代配内网镜像或认证。备份遇到符号链接／目录联接、磁盘不足或业务资料变化会停止，避免生成被误认为完整的备份。CPU／内存压力高时停止；依赖命令长时间无响应也会停止，仅终止本次命令及其子进程。

ZIP 安装没有 Git 仓库，仍使用[手工更新步骤](部署说明.md#windows-update)，不要把空目录当成已有部署更新。

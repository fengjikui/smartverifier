# 人员与权限管理

2026-10-20。当前使用本系统账号密码，暂不依赖公司 IDaaS。

## 谁可以做什么

| 身份 | 正品维护 | 人员与权限页面 / 接口 | 负责人账号配置 |
| --- | --- | --- | --- |
| 正品管理员 | 新增、编辑、导入、回收站及维护日志 | 不可见入口；手动输入地址显示无权限；接口拒绝 | 不允许 |
| 系统负责人 | 具备正品维护能力 | 新增普通管理员、停用 / 启用、改显示姓名、重置密码、查授权日志 | 网页不允许修改负责人 |
| 服务器部署人员 | 由实际登录账号决定 | 由实际登录账号决定 | 可在服务器终端初始化、增设或恢复负责人 |

`admin`、`root` 只是账号名称，不自动带来权限。默认本机 `admin / admin123` 仅用于体验正品维护，不能管理人员。旧版本已经配置的普通管理员不会自动升级为负责人。

## 第一个系统负责人怎样创建

不需要由开发者远程代配。你或公司 IT 等有服务器操作权限的人员，在部署电脑的项目目录运行：

```sh
npm run admin:owner
```

按提示输入本人账号、显示姓名及两次密码（至少12个字符，输入不显示）。名称可以自定，不要求叫 `admin`。脚本将带有 `owner` 角色的凭证写入被 Git 忽略的服务器私有配置，密码只保存随机盐与 scrypt 哈希；保留已有模型配置，不自动开放局域网。

停止原业务服务后，按原方式重新启动，例如 `npm run start:real`；只做资料维护也可 `npm start`。首次启动会把配置账号导入当前业务库，初始化操作在授权日志标记为“服务器配置”。使用负责人账号登录后，侧栏出现“人员与权限”：

```text
/inspections/marking/admin/users
```

只要是可信的服务器部署人员都能执行此初始化；它不是开发者专属操作，也不在网页提供公开注册入口。

### 找回、增设备份负责人

- 忘记密码或需要更新同一负责人：`npm run admin:owner -- --replace`，输入相同账号和新密码，重启服务。
- 增设备份负责人：再次运行 `npm run admin:owner`，使用不同账号。
- 负责人账号不能在网页停用、重置密码或修改姓名，避免误操作锁住授权入口。确需撤销负责人时，由部署人员在服务器账号配置中处理，保留另一位可用负责人，再重启；移除项会被停用并记录服务器撤销日志。
- 普通 `npm run admin:account` 仍可由部署人员配置旧式正品管理员；日常新增录入人员推荐使用网页。普通 `--replace` 不会把已有负责人意外降级。

## 日常配置业务录入人员

1. 系统负责人登录管理端，进入“人员与权限”。
2. 点击“新增管理员”，填写账号、显示姓名、初始密码及确认密码。创建权限固定为正品管理员，没有提升为负责人的选项。
3. 单独将账号和初始密码告知本人。密码不会出现在账号列表、授权日志或普通查询接口中。
4. 人员结束录入时点击“停用”，确认原因。系统提供默认原因，可按实际修改。
5. 继续参与录入时可“启用”；忘记密码可通过该行菜单重置。重置密码不会自动启用已停用账号。

停用、启用、改名和重置密码在网页保存后立即生效，**不需要重启服务**。受影响账号的旧会话撤销；停用人员下一次请求就不能继续访问。已经发出的操作请求可能已经完成，停用不回滚其历史合法录入。历史正品、图片、检测记录与原操作人姓名保留。

账号创建后不可改名为另一个账号，也不能复用已停用账号，避免将两个人的历史混在一起。显示姓名可以修改；历史日志仍保留当时姓名。没有永久删除人员的入口。

## 授权日志与防止误覆盖

“授权日志”记录操作人账号与姓名、目标账号、操作时间、操作类型、原因，以及不含凭证的变更前后状态。涵盖新增、停用、启用、改名、重置密码及服务器初始化 / 恢复 / 撤销。系统负责人可以按账号、操作人或原因搜索；普通管理员不能查询这些日志。

网页授权变更、会话撤销和审计日志在同一数据库事务中保存。日志无法写入时，整次变更回滚，不留下半次授权。多人同时修改同一账号时校验版本，后提交者会收到刷新提示，不能覆盖另一位负责人刚做的操作。

## 局域网访问仍由部署配置

人员角色与访问范围分别管理，网页不能解除仅本机限制。

```sh
npm run admin:access -- lan    # 开放协作录入
npm run admin:access -- local  # 恢复仅本机
```

修改网络开关后重启服务生效；普通人员的停用与启用则即时生效。模型调试页继续仅限服务器本机。网络、地址和 HTTPS 条件见[部署说明](部署说明.md)。

## 保存位置、升级与迁移

- 网页人员账号及凭证哈希保存在业务状态目录的 SQLite `admin_accounts` 表；授权日志在 `admin_access_events` 表。沿用原状态目录备份要求。
- `SV_ADMIN_USERS_FILE` 对应的私有配置保留负责人初始化与服务器恢复能力，默认 `var/config/admin-users.json`。迁移时同时复制它和 `.env.local`，不要只搬业务库或只搬账号文件。
- 旧文件账号首次导入为正品管理员，只有显式配置 `role: "owner"` 的账号才是负责人。
- 同一配置不反复覆盖网页停用、密码重置或改名；重启不会自动启用已停用人员。部署人员显式修改配置中的某个账号后，下一次启动会按新的服务器配置更新该账号并留痕；普通管理员原有停用状态保留，须由负责人明确启用。负责人通过服务器命令恢复后会启用。网页新增账号不受无关配置项更新影响。
- 已有人员账号时，遗失私有配置不会悄悄回退到默认试用密码。先恢复配置或通过服务器命令恢复负责人。
- 升级可能要求已有具名账号重新登录一次；正品和检验数据不因此改变。

后续如接入 IDaaS，认证入口负责可信身份验证，再映射到本系统授权角色；不会把“公司账号登录成功”直接当作拥有正品维护或人员授权权限。当前未实现企业认证联调。

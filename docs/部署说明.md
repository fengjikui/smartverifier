# 公司电脑试用部署与迁移

2026-10-21 更新。适用于根目录组织的鉴微当前版本，默认从 `main` 部署。启动入口、配置及数据目录见本文；不再使用旧版 `next/` 启动命令。

## 1. 本次交付与运行方式

业务服务运行在一台公司电脑上，平板浏览器访问它；业务服务通过配置的地址调用 VLM。平板不安装 Python、不保存模型密钥。公司已经有 VLM 服务时，业务电脑不需要显卡，也不需要下载模型权重。

当前可以：正品标准维护／导入 → 按物料与供应商选择正品 → 自主检测 → 自动定位、裁片、逐件真实比对 → 查看结论与不良数 → 人工填写电脑 MES。标准描述可留空；自主检测不上传 MES 附件，提交 MES 按钮禁用。模拟任务路径保留用于演练，不代表公司 MES 已接通。

管理员当前采用独立账号密码，暂不关联公司 IDaaS；检验端 IDaaS / MES 尚未接通，检验员使用同一明确标注的试用身份，不可当作真实人员隔离或正式上线版本。首轮先使用少量清晰样品；目前定位器适合绿色防静电台面、相互分离的深色封装。日常识别逐件串行，尚未进行多人容量验收。

## 2. 准备环境与代码

安装 Git、Node.js **24.x**、Python **3.12**。已完成本机 macOS 验证，以及 GitHub Actions 的 Windows Server 2025／Linux 验证；**目标公司电脑、真实公司模型和平板仍需现场核验**。已统一解释器路径、UTF-8 管道和文本文件编码，Windows 不调用 `pmset` 或强制读取 `os.getloadavg`，详情见 [Windows 兼容性检查](Windows兼容性检查.md)。

建议业务电脑有 16GB 或以上内存；图像工作器要求当时可用内存至少 8GiB，CPU 高负载时会暂停。本机还运行大模型时，内存需求另计，不能按业务服务容量估算。为正品原图、检验照片、派生图和备份预留磁盘空间。

```sh
git clone --branch main --single-branch https://github.com/fengjikui/smartverifier.git
cd smartverifier
node --version
npm ci --include=dev
```

仓库公开可读；也可将当前 Git 提交导出的源码 ZIP 拷到公司后解压。从项目根目录执行本文命令。使用 `npm ci` 按锁文件安装，先不要升级依赖。首次安装需要能访问 npm 和 Python 包源，内网受限时由 IT 配置公司镜像。

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -X utf8 -c "import PIL, cv2, lmstudio, psutil, httpx, openpyxl, defusedxml; print('Python依赖就绪')"
# .env.local 不存在时才复制；已存在时编辑原文件。
if (!(Test-Path .env.local)) { Copy-Item config/company-trial.env.example .env.local }
```

### macOS / Linux

```sh
python3.12 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -c "import PIL, cv2, lmstudio, psutil, httpx, openpyxl, defusedxml; print('Python依赖就绪')"
# 已有配置时不覆盖。
test -f .env.local || cp config/company-trial.env.example .env.local
```

无需复制开发电脑上的 `.venv` 或 `node_modules`。离线部署必须在相同目标系统、CPU 架构和 Python 版本准备依赖包，不能把 macOS 的二进制依赖直接搬到 Windows；本文不声称源码 ZIP 含离线依赖或模型。

**不用运行 `activate`、`Activate.ps1` 或更改 PowerShell 执行策略**。后续可统一用 `npm run python -- -m pip install -r requirements.txt` 更新依赖；该入口读取 `.env.local`，自动选择当前操作系统的解释器并启用 UTF-8。

## 3. 编辑配置与连接模型

打开项目根目录 `.env.local`，参照 [公司试用配置模板](../config/company-trial.env.example)：

| 项目 | 如何填写 |
| --- | --- |
| `SV_VISION_PYTHON` | 建议留空／不配置，自动选择本机 `.venv`；自定义环境时填写解释器路径，含空格无需额外激活 |
| `SV_STATE_DIR` | 默认 `./var/data`；也可用独立绝对目录，如 `D:/SmartVerifier/data` |
| `SV_HOST` / `SV_PORT` | 局域网试用为 `0.0.0.0` / `5190`；仅反代访问时可改为 `127.0.0.1` |
| `SV_VLM_PROVIDER` | 公司 HTTP 服务填写 `openai-compatible` |
| `SV_VLM_ENDPOINT` | 实际 VLM 基础地址，通常含 `/v1`；亦可填写完整 `/chat/completions` 地址 |
| `SV_VLM_MODEL` | 服务对外暴露的模型名，须由模型管理员确认 |
| `SV_VLM_API_KEY` | 如果服务有认证，填对应密钥；无认证留空 |
| `SV_VLM_TIMEOUT_SECONDS` | 首轮建议 90 秒；允许 5～180 秒 |
| `SV_MODEL_DEBUG` | 内网试用保持 `0`；本机需要查看模型输入输出时才改成 `1` |
| `SV_ADMIN_LOCAL_ONLY` | 默认 `true`，正品管理仅限服务器本机；`false` 允许其他电脑登录，必须先配置账号 |
| `SV_ADMIN_USERS_FILE` | 管理员账号哈希文件，推荐由 `npm run admin:owner` 自动配置 |

路径建议使用正斜杠，即使在 Windows 上也填写 `D:/...`。含空格的值用双引号包住。配置由 `npm run start:real` 读取；修改后重启业务服务。

从旧配置迁移到 Windows 时，如果原来写了 `SV_VISION_PYTHON=./.venv/bin/python`，请删除或注释这一行，让系统自动选择；也可明确改为 `./.venv/Scripts/python.exe`。相对解释器路径以仓库根目录解析，不能填写 `activate` 脚本或带 `-m` 等参数的整段命令。明确配置错误时不会偷偷换用系统 Python。

VLM 服务需要支持图片 Data URL、流式 Chat Completions 和 `response_format` JSON Schema。健康检查仅说明本系统启用了该适配器，**不代表已探测模型连通性**；实际上传一张照片识别，才完成端到端确认。不支持 Schema、超时或返回错误时，系统不会悄悄改用预设结果。详细协议见 [VLM 配置说明](VLM配置.md)。

如果公司电脑也使用 LM Studio，可优先使用其兼容 HTTP 服务，实际模型标识及 Schema 支持仍需验证。本机 SDK 方式设为 `lmstudio`，需另填对应模型的 `SV_VLM_TEMPLATE`，见 [本机说明](VLM配置.md)。不要复制本机 `hr-qwen` 别名或 macOS MLX 权重路径当作公司电脑配置。自动加载模型、模型下载和公司服务部署均不由本项目完成。

`.env.local`、业务数据与密钥不提交 Git。模型 API 地址属于服务器配置，平板只填写业务系统地址。


| 用途 | 本机地址 |
| --- | --- |
| 自主检测 | `http://127.0.0.1:5190/inspections/marking` |
| 正品管理 | `http://127.0.0.1:5190/inspections/marking/admin/standards` |

## 5. 让平板访问

让平板和业务电脑位于可互访的公司网络。将地址里的 `127.0.0.1` 换成业务电脑的局域网 IP，例如 `http://192.168.10.20:5190/inspections/marking`；IP 为示例，不能照抄。平板里的 `localhost` 指平板自身。由 IT 仅向试用网段开放 TCP 5190，确认无线网络没有客户端隔离。

当前拍照优先用网页相机连续取景：多次点快门后点击完成，统一添加照片。`getUserMedia` 需要 HTTPS 或本机等安全上下文，见 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia#security)。普通局域网 HTTP 或相机不可用时，使用 `capture="environment"` 调用系统相机后备，拍完仍回到本次拍摄页，可继续拍下一张；该属性只是提示，不同浏览器可能仍提供文件选择，见 [MDN capture 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)。检验员相册入口已隐藏，但尚不构成历史照片的强制拦截；目标华为平板上的取景、照片实际尺寸和系统相机返回仍待真机验证。

建议公司提供带受信任证书的内网 HTTPS 域名。反向代理应完整转发 **`/inspections/marking` 与 `/api/v1/inspections/marking`**，不剥掉前缀，保留查询、Cookie、原始 Host 和请求正文；设置 `X-Forwarded-For`、`X-Forwarded-Proto`。请求体上限至少 202MB，代理读取超时建议 200 秒，以覆盖图片导入与模型请求。不要将本机 1234 模型端口直接给平板使用。

公司使用专门 CA 时，沿用公司签发及平板信任方案。无现成网关也可运行 `npm run https`，通过 `SV_HTTPS_CERT_FILE` / `SV_HTTPS_KEY_FILE` 配置服务器完整证书链和私钥；本机临时联调另有独立测试证书生成入口。详见 [HTTPS 与平板相机](HTTPS与平板相机.md)。

### 5.1 正品管理员账号与临时协作录入

正品管理员暂时使用本系统账号密码，**无需接入公司 IDaaS**。检验端的模拟身份与管理员身份相互独立。

在服务器电脑的交互式终端，从项目根目录运行（Windows、macOS、Linux 相同）：

```sh
npm run admin:owner
```

这是系统负责人初始化命令，不限账号名称必须叫 admin。你或公司 IT 在服务器执行即可，无需开发者代配。按提示输入账号、显示姓名和两次密码。账号支持字母、数字及 `. _ @ -`；姓名可用中文，密码至少12个字符，输入不显示。重启后用负责人账号登录，在侧栏“人员与权限”给每位录入人员分别添加普通管理员，也可停用／启用、重置密码和查询授权日志。普通管理员看不到该入口，直接调用接口也会被拒绝。负责人本身只能由服务器配置，找回密码用 `npm run admin:owner -- --replace`；需要备份负责人时用新账号再运行一次。网页不能把普通管理员提升为负责人。完整说明见[人员与权限](人员与权限.md)。

助手默认写入 `var/config/admin-users.json`，文件只保存随机盐和 scrypt 哈希，自动把文件路径写进 `.env.local`，不改模型地址或其他业务配置。配置具名账号后，默认试用密码不再可用。Unix 文件权限为仅当前用户读写；Windows 上由部署人员限制目录访问。

临时开放与关闭：

```sh
# 先配置账号，再允许其他电脑登录
npm run admin:access -- lan
# 停止正在运行的业务服务（Ctrl+C），重新运行：
npm run start:real

# 用完恢复仅服务器本机；同样需要重启服务
npm run admin:access -- local

# 查看配置文件中的访问范围与服务器初始化账号（网页新增人员在页面查询）
npm run admin:access
```

只用于资料录入时也可用 `npm start`，不需要加载 VLM。开关实际对应 `.env.local` 的 `SV_ADMIN_LOCAL_ONLY=true/false`，支持 `1/0`，未填写默认为 `true`；账号文件不能隐式打开远程访问。**服务器初始化账号与网络开关在启动时读取**，终端命令只修改配置，不会自动重启或打断检测。网页新增、停用、启用、改名和重置普通管理员则立即生效，旧会话会撤销。操作系统环境变量优先于 `.env.local`，若仍不生效，请核对是否同时配置了同名环境变量。

开放后，把服务器的局域网地址发给同一可互访网络的录入人员，例如：

```text
http://192.168.10.20:5190/inspections/marking/admin/standards
```

地址中的 IP 换成服务器实际 IP；对方不能使用 `localhost` 或 `127.0.0.1`。服务需监听 `SV_HOST=0.0.0.0`，防火墙允许该业务端口。配置开关控制的是**正品管理权限**，不会关闭平板检验入口，也不会解除模型调试页的本机限制。不应把业务电脑端口公开到互联网；使用前述内网 HTTPS 代理可保护账号及资料传输。

恢复仅本机并重启后，之前已登录的远程会话也会被拦截；网页停用或重置普通账号立即失效。服务器端恢复密码或从配置移除账号，在重启后生效。本机旧版会话表自动补充凭证版本字段，既有正品和照片不变。

未配置账号文件时，保留 `admin / admin123` 的本机开发试用；默认密码不允许远程使用。只把开关改为 `false`、账号文件损坏或开关拼错时，启动会报错，**不会悄悄使用默认密码或放开访问**。此前单独设置过 `SV_ADMIN_USERS_FILE` 的部署也默认仅本机，需要明确将开关设为 `false` 后重启。

迁移管理员账号时，除业务状态目录外，还需复制 `.env.local` 和 `SV_ADMIN_USERS_FILE` 对应的私有文件（默认在 `var/config`，与 `var/data` 分开）。网页人员账号与授权日志已保存在业务 SQLite 中，凭证不进入 Git，迁移后应在目标电脑核对负责人登录、人员状态、路径和访问范围。

## 6. 原有正品与检测数据迁移

**Git 只包含代码、模板和明确标注的生成样例，不包含你录入的正品、检验照片、检测记录或私有配置。**

在原电脑停止业务服务，确认没有识别或导入正在执行，然后完整复制实际 `SV_STATE_DIR` 目录。默认源目录为：

```text
var/data/
  inspection.sqlite        # 标准、版本、任务、检测轮次、人工修正、审计等
  inspection.sqlite-wal    # 如存在也一并复制
  inspection.sqlite-shm    # 如存在也一并复制
  files/                   # 正品原图、缩略图、检验原图、定位图及裁片
  reports/                 # 已生成报告（如存在）
  vision-records/          # 定位及模型原始记录（如存在）
  vision-traces/           # 调试留档（如存在）
  ...                      # 其余状态文件也一起复制
```

先保留一份独立备份，再将完整副本放到目标电脑的状态目录。不要只拷数据库，不要覆盖目标电脑已有业务资料。目标机器修改配置中的 Python、数据目录和 VLM 地址，再启动。迁移后仍可读取记录中的旧图片引用，但不会重新开放旧 HTTP 路由；历史快照和判断不修改。较早导出的 Markdown 如含旧链接，请在系统中重新下载报告。

不要复制 `.venv`、`node_modules`、LM Studio 模型权重或整个开发电脑用户目录。配置按公司环境重新填，私有照片经公司允许的方式传输。原电脑和目标电脑不能把同一个活动数据库目录放在共享盘同时运行；备份副本使用本地磁盘。

如果希望公司从空库开始，不复制状态目录即可；系统启动后管理员重新录入标准。内置生成样例仍会作为明确标注的演示任务出现，不代表真实来料。

## 7. 交给现场前跑一遍

1. 健康接口正常，启用的 VLM 名称与公司配置一致。
2. 在服务器本机登录管理员，核对迁移后的标准数量，打开几张原图和说明；或先新增一条实际标准。
3. 平板打开自主检测，输入物料编号、确认供应商，能看到相应正品。
4. 上传一张清晰单件照片，完成真实检测。单件能跑通后再试双件和较差光照；不把生成样例当现场准确率证据。
5. 确认结论、不良数、原图和报告；自主检测 MES 按钮始终禁用。完成后刷新和重启服务，记录仍可找到。
6. 检查照片模糊或模型不可用时，页面提示重拍／重试，不能把未完成结果当成合格。

自动检查按顺序运行 `npm run check`、`npm run build`、`npm test`、`npm run test:python`；HTTP 页面回归需要前端构建产物，全新检出不能省略构建。Windows 与 macOS/Linux 命令相同，默认串行测试，不要求激活环境。测试只从 `.env.local` 读取 Python 解释器路径，不加载业务目录、账号文件或模型地址；也可用当前终端的 `SV_VISION_PYTHON` 覆盖。该 Node 测试部分用固定 HTTP 响应验证协议，不等于真实公司模型验收。`probe:real` 会调用真实模型，只应在明确准备好模型与资源时运行；研究脚本默认模型路径来自开发电脑，需要自行指定目标环境模型与模板。

## 8. 常见故障、更新和回退

| 现象 | 处理 |
| --- | --- |
| 页面 404 | 使用新的完整路径；核对反代保留前缀，不使用旧书签 |
| 平板打不开、电脑可以 | 核对 IP、主机绑定、端口、防火墙和无线隔离；电脑不要休眠 |
| 管理员在其他设备或反代登录被拒 | 本机试用的预期行为；直接在服务器登录，或按授权配置临时人员 |
| 上传或导入 413 | 检查服务单图 20MB／批量 200MB 限制及代理请求体上限 |
| 识别时报 Python 环境错误 | 检查 `SV_VISION_PYTHON`、虚拟环境依赖和运行权限 |
| Windows 提示找不到 `.venv/bin/python` | 注释旧配置的 `SV_VISION_PYTHON`，在 Windows 重新创建 `.venv`；不要复制 macOS 的环境 |
| `UnicodeDecodeError`／`UnicodeEncodeError`、GBK／UTF-8 报错 | 更新到兼容性修复版本、重启服务，脚本用 `npm run python -- ...`；文本清单保存为 UTF-8，JSON 导入也接受 UTF-8 BOM |
| 模型 401/404/超时/Schema 错误 | 核对 VLM 地址、模型名、认证、网络及 Schema；不要改成自动假结果 |
| 提示资源压力 | 释放内存，错峰运行；默认串行，不通过并行加压解决 |
| 查不到正品 | 确认使用正确数据目录，标准已启用且物料／供应商正确 |

更新前记录 `git rev-parse HEAD` 并备份整个状态目录。停止服务后，在无本地改动的部署目录执行 `git pull --ff-only`、`npm ci --include=dev`、按 requirements 更新 Python、重新构建和启动。若有本地修改先保留，不使用强制覆盖。应用回退应切回记录的 Git 提交，并使用匹配的**备份副本**验证，不能拿旧程序直接覆盖或降级活动数据库。

<a id="windows-update"></a>

### 8.1 Windows 已有部署更新：保留正品和管理员账号

推荐使用根目录的 `update-windows.cmd`，自动备份并校验资料，再更新代码、依赖和构建，失败立即停止并保留诊断。首次先取得脚本，完整使用及日志说明见 [Windows 一键更新](Windows一键更新.md)。以下保留手工更新方式，适用于 ZIP 安装或需要逐步操作的情况。

适用于已经使用本系统、录入过资料的 Windows 电脑。**在原项目目录更新，不删除项目，不重建业务库，也不重新创建管理员。** 以下命令在项目根目录的 PowerShell 中逐条执行；每条成功后再执行下一条，报错时先停下来。

**第一步：停止服务并备份。** 等待检测、批量导入结束，在运行服务的终端按 `Ctrl+C`；如果由系统服务托管，先停止对应服务。将根目录的 `.env.local` 和**整个 `var/` 文件夹**复制到项目外独立的带日期备份文件夹。默认包含：

| 保留内容 | 默认位置 |
| --- | --- |
| 模型地址、数据路径、访问范围、账号文件路径等配置 | `.env.local` |
| 正品资料、网页新增的管理员及密码哈希、人员状态、授权日志、检测记录 | `var/data/inspection.sqlite`，以及存在时的同名 `-wal`、`-shm` 文件 |
| 正品原图、缩略图、检测照片和其他派生资料 | `var/data/` 整个目录，不能只备份 SQLite |
| 服务器配置的负责人／管理员账号及密码哈希 | `var/config/admin-users.json` |

如果 `.env.local` 或启动环境设置了 `SV_STATE_DIR`、`SV_ADMIN_USERS_FILE`，还要备份它们**实际指向的目录／文件**；系统环境变量优先，不能只按默认路径备份。更新期间保留这些配置原值。升级可能要求重新登录一次，原账号密码沿用；既有普通管理员不会自动变成负责人。

**第二步：确认并更新代码。** 先记录当前版本，再检查分支和本地代码修改：

```powershell
git rev-parse HEAD
git branch --show-current
git status --short
```

将旧提交号记在备份旁。分支应为 `main`，`git status --short` 应没有输出；私有数据与配置被 Git 忽略，本来就不会列在这里。如有代码改动或不在 `main`，先保留并处理改动，不使用 `reset --hard`、`clean -fdx` 或删除目录来强行更新。满足条件后执行：

```powershell
git pull --ff-only origin main
```

**第三步：检查旧 Python 路径。** 编辑原 `.env.local`，若有 `SV_VISION_PYTHON=./.venv/bin/python`，将该行注释或删除，自动选择 Windows 的 `.venv/Scripts/python.exe`；原来已正确配置的 Windows 自定义路径可以保留。不要重新复制配置模板，不改原数据目录、管理员文件路径或 VLM 配置。已有正常 Windows `.venv` 时无需重建，也无需激活。

**第四步：更新依赖、检查和构建。**

```powershell
npm ci --include=dev
npm run python -- -m pip install -r requirements.txt
npm run check
npm run build
```

如果提示本机虚拟环境不存在，先按本文第 2 节创建 Windows `.venv` 并安装依赖，再继续；不能复制 macOS 的环境。需要完整自检时，在构建后依次执行 `npm test`、`npm run test:python`，它们使用隔离数据，不调用真实模型。

**第五步：按原方式启动并核对。** 原来使用真实识别时运行 `npm run start:real`；原来只做资料维护时沿用 `npm start`。从原地址登录，确认原账号可用、正品数量正确、几张原图能打开、管理员状态和访问范围仍符合原设置。无需再执行账号初始化命令或重新导入正品。

如果突然看到空库或原账号无法登录，先停服务，核对启动目录、`SV_STATE_DIR`、`SV_ADMIN_USERS_FILE` 与备份是否一致；不要先创建新账号或重新录入。需要恢复时，在停止服务的状态下使用完整备份副本核验，遵循本节前述回退要求。

**原来是下载 ZIP 安装的情况：** 如果项目里没有 `.git`、`git` 提示不是仓库，就不执行第二步的 Git 命令。完成备份后，从 [main 分支下载源码 ZIP](https://github.com/fengjikui/smartverifier/archive/refs/heads/main.zip)，先解压到临时文件夹，再将其中的代码复制覆盖到**原项目根目录**，保留原 `.env.local`、`var/` 和自定义数据／账号路径，不删除旧目录。随后继续第三至第五步。不要直接从新的解压目录启动，否则默认数据路径会变成一个新目录。

每次批量录入后和更新前备份，定期试恢复。长期运行的服务托管、备份轮换、HTTPS、监控和企业认证由后续正式部署阶段完善，本说明先保证试用可安装、可核验、可搬迁。

2026-10-19 仓库整理后，应用代码直接位于根目录，默认分支为 `main`。启动命令改为 `npm start` / `npm run start:real`，环境文件改为 `.env.local`，Python 环境为根目录 `.venv/`，默认业务数据为 `var/data/`。旧部署迁移时先停服务、备份，再把旧数据目录完整复制到新配置指定的位置；配置变量改为 `SV_HOST`、`SV_PORT`、`SV_STATE_DIR`、`SV_RECOGNIZER`，模型参数继续使用 `SV_VLM_*`。

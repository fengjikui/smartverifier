## 1. 项目概述（Executive Summary）

### 1.1 要解决的问题

现场检验员需要核对元件丝印与外观，并将结论、检查照片、不良数及报告录入 MES。新系统集中处理拍摄、AI 比对、人工核对和丝印项回填，减少重复录入，并保留可追溯的判断依据。

### 1.2 提议的解决方案

首轮采用触控优先的平板浏览器 H5；选择 MES 任务后自动关联正品标准，支持分次拍摄与识别，生成明确结果后可直接回填丝印项。人工复核与修正是可选能力，不要求逐个确认；低置信度提示关注，无法判读等未完成内容仍须先处理。后台集中执行规则，保留以后接入鸿蒙或 WeLink 的边界，详见[架构建议](架构说明.md)。

### 1.3 首轮成功标准

以下为待实现并验证的验收标准，不是已通过的测试结果。

| 编号 | 可验证标准 |
| --- | --- |
| AC-01 | 本轮仍有未识别、识别失败、待重拍、结果缺失或最新依据下未处理完成的内容时，服务端拒绝回填；有明确有效结果的低置信度提示或可选复核未打开，不单独阻止提交。 |
| AC-02 | 在先识别 8 个、再补 2 个的用例中，依据未变时只处理新增 2 个；修改任务说明后，已有元件也按新说明重新判定，复用照片。 |
| AC-03 | 未人工修改时采用有效 AI 结果，修改后采用人工结果；按最终不合格元件计数，任意一个不合格使整体不合格，回填值只有合格／不合格。 |
| AC-04 | 人工改判额外标记且可检索，追溯 AI 原判及置信度、人工结果、人员和原因；报告披露现场说明与冲突，正品维护日志可查操作人及变化。 |
| AC-05 | 首次及重检回填失败都明确提示；重检新结果只有成功回填后成为当前有效结果，失败不替换上次有效结果，重试不产生重复写入。 |

真实识别效果采用人工标注样本评估，具体误判／漏判目标待实拍样本与业务共同确定；不预造准确率。等待时间预期为每件几秒量级可接受，具体时延以实际模型、图片和排队测量，尚未作出已达成承诺。

## 2. 用户体验与功能（User Experience & Functionality）

### 2.1 使用角色与设备

- 检验员：在目标平板拍摄、补拍、识别、核对、补充说明、修正与回填。
- 正品管理员：维护正品库和标准说明，不由普通检验员上传正品图片。
- 系统维护／核验人员：按授权查看人工修正样本、核验原因与改进效果；首轮可由管理员承担，不增加现场检验员必填工作。
- 接口及部署人员：对接 IDaaS、MES 与公司模型服务，协助正式试用。
- 目标平板：HUAWEI MatePad 11.5 S 灵动款，HarmonyOS 5，11.5 寸、2800×1840。实际页面按可用视口适配，不把屏幕物理像素直接当作 CSS 尺寸。
- 先本机开发，后公司电脑部署；人员规模可能增加至几十或上百，不等同于同数量模型任务并发执行。

### 2.2 主流程

登录 → 选择任务并关联标准 → 拍照／选图 → 前处理与 AI 识别 → 结果概览 → 检查本轮完整性 → 回填并保存 MES 丝印项。

人工复核／修正从概览或元件详情按需进入，不是每个元件必经的正常通道。低置信度突出提示但不强制复核，默认主操作保持提交顺畅；未来可选的自动回填另行设计。

拍摄、识别、核对可多次往返。没有固定应检数量，检验员决定何时结束，但不允许将已拍、尚未得到明确结论的内容自动略过后直接部分提交。未来是否按应检样本数约束提交，见 BIZ-04，当前不据此增加固定数量门槛。

### 2.3 用户故事与验收条件

#### US-01 · 登录与选择任务

作为检验员，我希望看到与自己关联的检验任务，并快速定位单号，以便开始检查。

- 正式登录对接公司 IDaaS，获得可信人员标识；开发身份只用于明确标识的本地测试。
- 显示 MES 返回的任务，按单号、物料编号、供应商关键词查询，标记任务是否已有结果。
- 选择任务后按物料编号＋供应商名字关联正品标准，当前先按一套标准考虑。
- 缺少标准时提示「缺少正品基准，请联系管理员」，不能检测，不提供检验员临时上传正品图的绕过路径。
- 任务结果归属任务，不绑定为原操作人的个人记录；多人实际处理与草稿共享细则见 BIZ-02。

#### US-02 · 分次拍摄、补拍与替换

作为检验员，我希望先拍一部分、看结果后继续补拍，以便不用一次完成所有摆放。

- 支持拍照与相册、多次添加、明确删除拍错或不合适的照片。
- 支持单张一个或多个元件，要求各元件足够清晰；具体数量建议待平板实拍。
- 当前每个元件只拍丝印面；重拍替换对应原照片，不把同一元件重复计数。
- 识别后仍可继续添加，依据未变时只识别新增部分，保留未变动部分的结果。
- 质量低到无法判断时，对照片标记「图片质量过低，请重新拍照」，不判元件不合格，也不生成不确定检验结论。
- 定位或模型处理失败应成为可恢复的处理状态，不能凭空生成合格结果。

#### US-03 · 基准比对与现场补充说明

作为检验员，我希望系统理解正式标准和本次现场补充要求，以便处理标准未涵盖或允许变化的情况。

- 自动使用正品图与自由文本标准说明，对文字、Logo、排版、外形、颜色等进行比对。
- 管理员可在说明中注明允许的可变差异，不将任意差异一律判为不合格。
- 检验员可补充本次任务说明，记录与本次检测关联，不直接修改正品库。
- 要求冲突时以现场说明为准，报告保留标准与现场说明，显著披露冲突及实际采用的现场指示。
- 修改补充说明后，已有元件也按最新说明重新判定，无需重拍。
- 每个元件输出置信度与原因，区分可读但把握偏低和实际无法判读；阈值可配置并经真实样本验证。
- S／5 等易混字符结合待检图与正品图比较字形，不仅依赖 OCR 字符串；证据不足时降低把握，无法判断时不得强行产生可提交结论。

#### US-04 · 平板复核与人工修正

作为检验员，我希望需要时能迅速查看元件并修正误判，其他情况下直接提交明确结果，减少重复操作。

- 总览可查看元件缩略图与结果，轻量提示低置信度数量和原因；进入详情可查看清晰图片、识别内容和差异依据，不要求逐个进入详情。
- 可以结合实物直接核对，在平板修正元件结论，不必到电脑端改判。
- 修改原因优先点选，例如「AI 识别错误，人工核对后修正」，可补文字或语音。
- 保留 AI 原判、原置信度、人工修正、修改人和原因，并标记曾人工修正；未改判时汇总有效 AI 结果，改判后使用本次人工结果。
- 更新说明后，保留旧人工历史、展示最新依据下的新结果及建议复核；有明确有效新结果时不因未打开复核而禁止提交。原 DES-01 的必审默认已按本次要求调整。
- 低置信度只表示对判断的把握偏低，不等于不合格，也不新增第三种检验结论。具体提示语与入口详见[复核设计](复核与审计.md)。

#### US-05 · 完整提交与报告

作为检验员，我希望明确知道本次检查是否完成、哪些内容仍需处理，以便正确回填结果。

- 提交前检验本轮保留的全部照片与元件是否处理完成；未识别、识别失败、待重拍、缺少有效结论或最新依据下尚未更新的内容必须先处理。可选人工复核不是完成条件。
- 界面和服务端都执行完整性规则，不能通过隐藏失败项或绕过按钮提交成功部分。
- 拍错／不合适照片仍可明确删除或替换；删除不代表该照片已合格，也不由系统自动排除未处理内容。
- 当前没有规定的应检样本数，不因假定数量拦截；未来若业务有规则，再确认数据来源与校验口径。
- 不良数按元件统计，任意一个不合格使任务整体不合格；没有完成有效检测内容时，不产生可回填的最终结论。
- 报告包含任务关联、照片与元件对应、识别内容、结论及差异说明、现场自定义说明、人工修正与汇总信息。
- 采用图文 Markdown 方向，图片与编号不遮挡丝印；实际 MES 包装与查看方式按 MES-04 确认。
- 2026-10-17 补充：报告及元件详情对丝印文字逐行对照，采用稳定字宽；双方不一致的字符以红色等视觉标记突出，并说明行号、位置及差异类型。一致内容正常显示；插入或缺字先对齐，避免后续整串误标。首轮采用文字差异标记，原图中的逐字符定位另行评估。允许变化与人工改判按当前检测依据解释，不以字符串不同自动判不合格。
- 不以模型一句汇总结论代替服务端计算不良数与任务整体结论。

#### US-06 · MES 回填与重检

作为检验员，我希望知道 MES 是否真正保存成功，并能在需要时重检，以便结果可恢复、可追溯。

- 仅回填 MES 丝印检测项；整张检验单仍由人在 MES 最终提交。
- 任务结论、附件、不良数及人员等经服务端提交，具体字段与鉴权仍待 MES 合同。
- 首次与重检回填失败都明确提示，保留待提交内容并支持幂等重试。
- 区分检测完成、回填处理中、成功及失败，不把点击提交视为 MES 已保存成功。
- 重检可复用、调整或在新轮清空照片，但不删除历史轮次。
- 新结果成功回填才成为当前有效结果，失败时上次成功结果保持有效。

#### US-07 · 管理正品标准

作为管理员，我希望维护准确的参考图与说明，以便任务能自动关联正确标准。

- 独立管理入口提供增删改查，字段包括物料编号、供应商名字、图片与自由文本说明。
- 按当前组合维护一套标准，防止同组合出现无法区分的多份有效标准。
- 缺少或找不到标准的任务，补齐后可继续检测。
- 标准维护与检验员现场说明分开；检测记录需能追溯本轮实际使用的图与说明。
- 正品新增、编辑、删除／停用自动留痕，记录操作人、时间、对象、字段变化及图片版本，支持检索；标准更新不静默改写历史检测依据。
- 少量管理员默认采用 IDaaS 身份＋服务端稳定人员标识白名单，首个管理员由部署配置初始化；权限维护与变更留痕，不另建独立密码体系。此为委托设计默认，正式人员身份字段待对接。
- 批量导入是否纳入首轮及其形式，由实际资料组织方式决定；不是已实现能力。

#### US-08 · 人工修正样本检索与改进核验

作为获授权的维护人员，我希望筛选并分批查看人工修正案例，以便区分模型错误、质量漏报、处理流程、标准说明或任务难度问题。

- 人工修正记录额外标记，关联任务、轮次、元件、原图与裁剪图、AI 输出及置信度、检测依据、人工结果和操作历史。
- 记录从首次使用开始采集，后台支持按日期、物料、供应商、任务、修正方向、置信度和原因查询。
- 支持按批次整理核验资料，下载／导出交互随后台设计细化；后续主动发送方式需明确渠道、对象与触发规则，当前不自动推送。
- 核验结果与现场修改原因分开保存，人工修改不直接等于模型错误，不经核验自动成为训练标签。
- 改进模型、提示词、阈值或拍摄流程后，用标注样本评估；同时抽查未修正样本，不只用改判率衡量整体准确率。

### 2.5 当前不包含的范围（Non-Goals）

- 自动提交 MES 整张检验单。
- 普通检验员维护正式正品库。
- 以网页聊天作为主检测入口，或要求日常手工裁剪、旋转图片。
- 当前阶段的多面拍摄、多套合格样式、鸿蒙完整原生端与 We码小程序实现。
- 没有依据时输出假货概率、以图像生成补写模糊丝印，或将失败当成合格。
- 当前模型方案的平板离线推理，以及尚未约定的历史删除规则。

## 3. AI 系统要求（AI System Requirements）

### 3.1 工具与处理能力

1. 原图接收、元件定位、裁剪与方向调整；保留可追溯的位置和原图引用。
2. 照片／元件质量反馈，不能判读时进入待处理状态。
3. 读取本轮正品图、标准说明、现场说明，生成可追溯的检测依据。
4. VLM 识别与比对，输出可校验结构化结果；当前沿用已讨论的本地千问模型方向，具体加载标识与接口在接入时核实。
5. 按元件保存识别文字、差异说明与判定；非预期格式、缺项、请求失败不得直接当作有效检测结果。
6. 任务进度查询、受控排队、分次处理与失败恢复，模型进程不依赖某个网页一直打开。
7. 重新判定时关联最新说明，防止旧请求晚返回覆盖新说明下的结果；具体版本与并发机制在技术设计中落实。
8. 输出每件判定置信度、原因与可判读状态；保留分数属于哪次 AI 结果的关联，不将原 AI 分数复用于人工结论。

### 3.2 前处理边界

裁剪与旋转改善输入组织，不承诺恢复原图不存在的文字信息。首轮采用可解释的图像处理或轻量定位技术，具体方案通过样本验证选择；模型接收的检测图不因报告编号而遮挡丝印。图像增强若采用，保留原图与处理说明，不使用生成式补字作为判定证据。

### 3.3 评估与测试

- 使用人工确认预期结果的合格、不合格、允许变化和模糊样本；合成样本与真实样本分开标记。
- 测试单元件、多元件、不同摆放方向、背景与大小，分别记录漏定位、误定位、裁剪不全和旋转问题。
- 记录元件级误判、漏判和无法判读情况，并检查任务级结论及不良数汇总。
- 用 S／5 等真实混淆字形、略模糊但可读及完全不可读样本检验置信度排序；明确不合格也可能高置信度，不能用合格程度代替判定把握。
- 校准低置信度提示阈值，观察高置信度误判与未被修正样本；具体分数未经标注样本验证不宣称等同于真实正确率，研究依据及设计边界见[置信度设计](复核与审计.md)。
- 验证现场说明优先、报告冲突披露、修改说明后的重新判定和人工修正追溯。
- 记录每件处理与排队时间，不只统计模型一次调用耗时。
- 重大交付由助手实际试用拍摄／选图、补拍、修正、报告和回填路径；真实平板与真实 MES 分别验收。

## 4. 技术规格（Technical Specifications）

### 4.1 架构组织建议

建议采用独立 API 后台、模块化业务服务与受控识别工作进程。后台集中实现身份适配、正品库、任务／检测轮次、图像与模型处理、人工核对、报告及 MES 集成。此为工程建议，具体框架和数据库产品待下一阶段技术设计，不要求用户预先选择。

业务 API 面向照片标识、元件标识、任务和轮次提供操作，不直接暴露某个浏览器或手机的本地路径。浏览器、未来原生或 WeLink 客户端可共用相同业务规则；拍照、选图、登录入口、语音等在客户端适配层实现。

### 4.2 数据与状态的必要区分

| 对象 | 主要关系与约束 |
| --- | --- |
| 检验任务 | 对应 MES 任务与检验单；记录物料和供应商，数据归属任务。 |
| 正品标准 | 物料＋供应商匹配；检测轮次保留使用依据，不受后续标准编辑静默改写。 |
| 检测轮次 | 一轮内多次补拍与识别；保留现场说明及其变化。 |
| 照片与元件 | 一张照片可能含多个元件；重拍替换不重复计数，原图与衍生图可对应。 |
| AI 判定与人工复核 | AI 原判、置信度及原因保留；人工修正独立标记，未修正用有效 AI 结果，已修正用本次人工结果。 |
| 核验样本与维护审计 | 关联人工修改案例、核验结论与基准维护的变化，分清现场原因与后台核验结果。 |
| 报告与回填记录 | 关联确定的结果版本与附件，保存处理状态、成功依据和重试关系。 |
| 当前有效结果 | 只在新结果确认成功回填后更新；与重检草稿、未处理项分开。 |

照片处理状态、人工核对状态和 MES 回填状态不是额外的合格／不合格枚举；数据库字段与具体状态机在后续设计确定。

### 4.3 集成边界

- IDaaS：协议、Token、人员字段、刷新与可信身份传递见 AUTH-01～03。
- MES：保持已确认的任务读取、结果回填两个业务用途；附件、枚举、不良数零值、保存回执和重检更新见 MES-01～05。不能假定真实合同已确定。
- 模型：通过后端适配接入，不让平板直接持有模型或 MES 服务凭证。
- 平板：拍摄、相册、权限、语音与页面恢复进行实机测试；浏览器相机实时流的安全上下文条件见[架构建议](架构说明.md)。
- WeLink／鸿蒙：属于后续客户端选择；身份适配与终端能力需要新增验证，不改变当前 IDaaS／MES 业务约定。

### 4.4 数据访问与操作追溯

- 服务端核验可信身份与任务访问范围，不能仅依赖前端传入工号作为认证。
- 管理员维护标准，检验员维护本次任务说明与复核结果，二者分权。
- 管理员白名单匹配已认证的稳定人员标识，服务端逐次授权；管理入口隐藏与否不替代权限检查，后续可映射公司可信管理员组。
- 正品维护和管理员授权变化自动留痕；内部样本检索与批量资料访问同样受后台权限控制。
- 原图、报告与历史记录的访问随任务权限，保留操作人、原因及所依据的说明。
- 部分提交校验、回填资格、计数和有效结果切换由服务端落实；重复请求与旧结果回写需受控。
- 多人处理细则、历史删除权限与正式保存时长不在本草案中假定，分别按 BIZ-02、IDEA-02 与 OPS-01 确认。

### 5.2 主要不确定性与处理

- 多元件清晰度与自动定位：等目标平板实拍，不把数量档位当作已验收上限；定位失败不能成为遗漏元件的正常提交路径。
- 模型时延与并发：采用受控任务队列，记录实测再调并发。遵守本机负载、内存与可取得热状态检查要求，不并发压满用户电脑。
- 自然语言说明与冲突披露：以明确样例验证允许变化、现场优先与报告解释；不能以补充说明存在就声称所有冲突都能自动完美识别。
- MES 保存结果不明确：协议需区分确定失败与超时未确认，按接口能力核实并幂等重试，不把未知状态误显示为成功。
- 任务身份与历史范围：多人草稿、个人历史筛选、删除权限仍需业务核实，不回到按创建人私有的任务数据模型。
- 客户端演进：先验证 H5 能力，再决定是否开发原生或 WeLink 版本，避免把网页复用误理解为原生页面自动生成。

### 5.3 尚待确认但不阻塞草案的事项

- BIZ-04：是否存在应检样本数要求、来源和校验规则。
- IDEA-01／02：个人历史入口、日期组织方式及维护／删除规则。
- IDEA-03／04：自动回填的本轮范围与条件，改判案例主动发送的渠道与触发方式。当前不把低置信度可选复核变成强制确认。
- AUTH、MES、BIZ、OPS 外部事项见[对外清单](待对接事项.md)。
- 设计默认与需复盘内容见[设计备忘](复核与审计.md)；本轮未确定具体框架、数据库、像素级界面或正式性能阈值。


## 2026-10-18 试用范围补充：MES 延期与自主检测

用户确认 MES 接口约两个月后才能提供。在此期间支持独立“自主检测”：查询物料、选择供应商和管理员维护的正品标准，上传照片真实识别，展示结论及不良数量，回填按钮禁用。人员在电脑 MES 手工填写这两项，暂不通过本系统上传附件。自主记录单独存储，不创建 MES 检验单；说明可空，质量、增量、人工修正和标准快照规则不变。

同时支持按已启用正品库自动提供的模拟 MES 任务验证任务关联，数据来源必须明确标注。任务新增、修改、删除仍不由检验员或正品管理员维护。正式接口接入后的自动关联流程不变。实施与验证见《自主检测与模拟 MES 试用说明》。

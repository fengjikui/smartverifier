# MES 接口沟通方案（建议稿）

2026-10-29。用于双方确认合同，**不是 MES 已承诺或已经实现的接口**。本系统当前仅有模拟源与回执；接口地址、编码、鉴权和历史范围由 MES 负责人确认。

## 已确定的职责

- 读取当前检验员有权访问的任务；本系统不新增、编辑、删除 MES 任务，也不向正品管理员拉取全员任务。
- 只回填并保存“丝印检测”这一项：合格／不合格、按元件计的不良数、原始照片与图文 Markdown 报告。整张检验单仍由人工在 MES 最终提交。
- 正品通过**物料编号＋型号**关联，供应商选填且不参与唯一匹配。没有标准则阻止检测并联系管理员。
- 一轮已拍内容须全部有有效明确结论才能回填。任一元件不合格则整体不合格；不良数不等于照片数。
- 重检期间保留上次有效结果，新的保存被 MES 确认成功后再切换。首次或重检失败均提醒，超时结果不明确时先查回执，避免盲目再次写入。

## 推荐交互

平板只调用本系统同源后台，后台核验身份后请求 MES。公司 IDaaS 的 Token 是否可用于 MES、需要的 audience／scope、服务身份和人员委托方式需双方确认；不信任前端手填工号，也不默认任意 Token 可以跨系统透传。

### 1. 人员任务列表

建议 `GET /quality/inspection-tasks?q=0016&status=unfinished&page=1&pageSize=25`，人员范围从可信身份取，不用客户端自选用户 ID。

建议返回：

```json
{
  "items": [{
    "taskId": "MES稳定主键",
    "inspectionNo": "IQCF26090500016",
    "materialNumber": "000123",
    "modelNumber": "SV358",
    "supplierName": "华信电子",
    "status": "unfinished",
    "revision": "12"
  }],
  "total": 1,
  "page": 1,
  "pageSize": 25
}
```

编号／型号按字符串保留前导零。关键词匹配单号、物料、型号及供应商；状态“已完成”具体指丝印项保存还是整单提交，须 MES 明确定义。需明确已完成保留多久、分页／排序稳定性、手动刷新、整单锁定后能否重检、人员交接与冲突处理。状态筛选不删除 MES 数据。

### 2. 附件先上传，再原子保存丝印项

推荐由 MES 提供附件上传接口（或签名上传地址），返回永久附件 ID；再一次提交结论与附件引用。这样避免大照片随结果重试而重复上传。图片和报告须在 MES 接收端可读，不能引用当前只凭本系统 Cookie 可访问的临时 URL。

建议 `PUT /quality/inspection-tasks/{taskId}/items/marking`，携带 `Idempotency-Key` 与可选 `If-Match`。业务体示例：

```json
{
  "inspectionNo": "IQCF26090500016",
  "verdict": "FAIL",
  "defectCount": 2,
  "sampleCount": 6,
  "sourceRoundId": "本系统检测轮次ID",
  "sourceRevision": 8,
  "operatorId": "可信人员标识",
  "attachments": [
    {"id": "photo-001", "name": "P001.jpg", "kind": "original-photo"},
    {"id": "report-001", "name": "marking-report.md", "kind": "report"}
  ]
}
```

`sampleCount` 和来源轮次是建议追溯字段，是否接收由对方决定；`operatorId` 必须与已验证身份一致。PASS／FAIL 对应 MES 实际枚举码待确认；本系统不用“不确定／不涉及”。建议合格时不良数传 0，仍须对方确认。

建议成功回执含 `receiptId`、`taskId`、`itemCode=marking`、`savedAt`、新的 `revision` 和附件 ID；只有确认“已保存”才更新本系统有效结果。若返回 202，则必须提供状态查询，不能把“已受理”直接显示为保存成功。

### 3. 幂等、冲突与查询

- 幂等键建议由任务＋轮次＋冻结结果版本派生，所有相同内容重试复用同键；同键不同请求体拒绝。MES 端保存幂等回执，双方约定保留期限。
- 查询接口建议按幂等键或 `receiptId` 读取保存状态；网络超时后先查询，确认未保存才重试。
- `409`／`412` 表示任务版本变化或整单锁定，展示具体原因，由人员刷新核对；不覆盖更新的结果。
- `401` 重新认证，`403` 明确无权限；`429`／暂时性 `5xx` 有界退避重试，永久字段错误不循环重试。附件成功但结果失败的孤立附件由 MES 按期限清理或提供删除能力。
- 服务间 HTTPS 使用公司 CA 并校验证书；接口日志保留请求 ID、任务、轮次及回执，不记录 Token 或照片正文。

## 请 MES 方优先确认

1. 物料编号、**型号**、任务稳定主键、单号是否都能返回；缺型号怎么补齐。
2. 人员任务授权、IDaaS／服务身份的对接方式、Token 生命周期和权限范围。
3. 合格／不合格编码、不良数 0、仅保存丝印项是否可独立于其他项进行。
4. 附件上传协议、大小／数量、Markdown 与图片关联方式、留存与下载授权。
5. 保存成功回执、幂等查询、重检覆盖、多人冲突和整单最终提交后的锁定规则。
6. 已完成任务状态定义、历史范围与手动刷新；无需管理员全员任务查询。

若对方只能提供一个 multipart 接口，可将上述业务 JSON 与附件一起提交，仍需同样的幂等和可查询回执。建议优先采用“附件上传＋结果原子保存”，不要同时维护多套正式协议。

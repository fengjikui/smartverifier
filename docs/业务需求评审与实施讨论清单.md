## 一、这次会议要带走什么

希望会议结束时，能够回答以下五件事：

1. 第一阶段具体帮助哪类检验人员、检查哪些物料、解决哪一步工作。
2. 什么叫“正常差异”“值得怀疑的差异”“看不清”和“不能判断”，分别如何处理。
3. 一张参考图如何建立，现场如何拍照，一张照片有很多器件时究竟检查哪些。
4. 手动取景和 Agent 自主选区如何配合，结果如何复核并追溯到实物。
5. 谁提供真实样本，按什么指标验收，谁负责部署、维护和业务拍板。

**会议产物**：一期范围、差异规则表、标样建立规则、采集与抽样规则、结果及复核流程、试点验收表、待办责任人和截止日期。暂时无法确定的事项，写清“缺什么证据、谁补、何时再定”。

### 1.1 建议参会人员及会前材料

| 角色 | 建议带来的材料或信息 |
|---|---|
| 一线检验员 | 日常一批来料的实际操作过程；常见照片、难拍照片；最费时间的步骤 |
| 质量负责人 | 现行检验与放行规则、异常分级、复核流程、漏检与误报的业务后果 |
| 工程／物料专家 | 一期候选料号、封装信息、丝印解释、已知合法版本差异、标样来源 |
| 采购／供应链 | 来料批次与供应商记录方式、疑似异常后的取证和沟通流程 |
| IT／WeLink 对接人 | 手机和网络限制、内网部署条件、账号体系、WeLink 测试条件与上线要求 |
| 项目负责人／研发 | 当前功能演示、尚未实现的部分、待决策事项、人员和排期约束 |

材料不齐也可以开会，但应避免仅凭一张理想照片确定准确率目标。真实照片、供应商资料和标样凭证放在业务批准的位置；仓库保留脱敏后的规则、文档和样本索引。

## 五、用真实例子现场走通的场景

以下是拟验收场景，不表示当前全部实现。业务方为每一类提供实物或脱敏原图，并确定可接受的结果。

| 场景 | 现场应验证的问题 | 建议接受的行为 |
|---|---|---|
| 清晰的正常单颗器件 | 参考正确、关键字段能否核对 | 展示读字与对照证据，明确只覆盖该件及可见面 |
| 合法批次码变化 | 日期／批次变了是否一律报异常 | 按已批准规则解释变化，不把所有不同都判异常 |
| 关键字符只差一笔 | 能否区分细微文字差异，模糊时是否补字 | 保留逐字结果、指出位置，不清楚就明确不确定 |
| 反光或失焦 | 能否识别证据不足并给出可执行指引 | 提示具体补拍动作，不能显示通过 |
| 密集多颗器件中夹一颗异物 | 是否只检查最清楚的一颗 | 按确定的覆盖规则检查，显示已检、未检和异常位置 |
| 手动框选一颗器件 | 模型是否仍引用框外信息 | 发送并展示实际裁片，说明判断范围 |
| Agent 选错目标或转错方向 | 人能否立即纠正，过程是否可回看 | 可接管、重选或终止，保留选区与实际图片 |
| 自由比例、缩放与旋转同时使用 | 确认前后内容是否一致 | 原图不改写，最终预览与模型输入一致，框形状可继续调整 |
| 缺标样、标样版本不匹配 | 会不会拿任意参考图强行比较 | 明确无法比较，进入补建或人工确认流程 |
| 更换图片后的连续追问 | 会不会把上一颗的内容当成本颗证据 | 清楚绑定当前对象，比较旧图时显式引入相应图片 |
| 多人同时提交、锁屏或断网 | 是否重复提交、丢记录或永久等待 | 任务状态可恢复，失败可重试，复核记录可查 |
| 人工推翻模型或标样被撤销 | 是否能追溯原判断和受影响记录 | 保存更正理由和版本，按已定流程回溯 |

## 六、验收表：会议先定口径，再填阈值

下表不预填准确率和性能数字。阈值要结合样本难度、异常代价、人工基线与可用资源确定。照片数量、实物数量、批次数量分别统计，避免把同一颗的多张照片算成多个独立样本。

| 指标 | 建议定义／需要明确的口径 | 门槛与样本量 | 验收人 |
|---|---|---|---|
| 关键字段完全正确率 | 正确读出的关键字段数 ÷ 有人工真值的必检字段数；不可读和跳过字段另列，不悄悄移出分母 | 待定 | 待定 |
| 异常检出率与漏报率 | 检出率＝正确定位且指出异常的件数 ÷ 有真值的异常件数；另统计异常件被误当正常的比例。无法判断和未检单列，不记为通过 | 待定 | 待定 |
| 正常件误报率 | 被错误报为异常的正常件数 ÷ 有真值的正常件数；合法版本变化纳入正常样本 | 待定 | 待定 |
| 需补拍／无法判断比例 | 明确按首次检测件数还是照片数统计；最终仍无结论的实物单列 | 待定 | 待定 |
| 检测覆盖 | 计划检查件数、实际检查件数、正确对应到实物的件数；抽检不得按整批全检计算 | 待定 | 待定 |
| Agent 选区与工具成功率 | 分别统计选对目标、有效返回裁片、旋转正确和最终可用结果；文字声称执行不算成功 | 待定 | 待定 |
| 单任务耗时 | 从用户发送到可复核结果，包含排队、预处理、推理和 Agent 重试；报告中位数及 95% 的请求能在其内完成的耗时（P95） | 待定 | 待定 |
| 峰值可用性 | 在约定手机数、任务量和图像条件下，排队时间、失败率与恢复情况 | 待定 | 待定 |
| 人工总工时 | 拍照、调整、等待、补拍、核对及记录的总时间，与原流程同口径比较 | 待定 | 待定 |
| 追溯完整性 | 是否能找到对应原图、实际裁片、参考版本、观察结果、人工结论及责任人 | 待定 | 待定 |
| 现场与恢复能力 | 指定手机、浏览器、网络与中断场景逐项通过；企业权限与备份按一期范围验收 | 待定 | 待定 |

需要特别确定：

- “没有检测出异常”必须区分为误当正常、无法判断和未检；后两项不能记为通过。
- “关键字段正确”是字符正确、整行正确还是所有必检字段同时正确，不能混用。
- 真实异常或假货样本不足时，报告实际数量与能力边界；小样本中没有漏报不代表生产中不会漏报。
- 样本按实物／批次分组后再划分用途；不要用反复调试过的同批照片作为唯一验收证据。
- 一次功能演示、一次识别更快、一次裁剪后文字更多，都不能替代固定测试集上的评价。

| 业务与样本准备 | 明确一期物料；确认一张主参考图的来源与适用范围；建立差异规则和测试样本 | 业务负责人确认范围，质量确认规则与标样，样本可追溯 |
| 小范围试点 | 在真实手机和现场网络上完成拍照、手动／自主查看、指定检查项、证据展示与人工复核 | 验收样本和关键操作场景达到约定标准，正常业务有人工兜底 |
| 扩大使用 | 按实际需要增加料号、多人账号、参考版本、WeLink、系统对接或更大规模处理 | 负载、权限、运维和收益得到现场验证 |

是否把 Agent 网页入口、参考库、逐颗计数、WeLink 登录或批次管理放入一期，需要逐项明确。不要将所有后续能力默认塞入一次试点，也不要遗漏一期已经承诺的能力。

讨论用后置项：未经验证的真假概率、全品类通用检测、无人复核自动放行、依据一张局部图推断整批、复杂训练流水线。业务若坚持一期需要，应补齐相应真值、规则、资源与验收方案。

## 九、主持人结束会议前核对

- [ ] 是否明确一期交付的是哪种观察／比对能力，以及由谁决定业务处置？
- [ ] 是否有具体物料范围、一张可信主参考图、可执行的差异规则？
- [ ] 是否约定多颗器件的检查覆盖，避免局部结果被理解为整批通过？
- [ ] 是否保留手动与 Agent 两条方式，并说明自主查看的范围与失败接管？
- [ ] 是否安排真实样本、人工真值和独立验收，不用演示效果代替准确率评价？
- [ ] 是否明确照片不合格、缺标样、意见冲突、断网与服务异常时怎么办？
- [ ] 是否给网络、账号、WeLink、数据和运维事项指定了可落实的负责人？
- [ ] 是否记录必做与后置范围，并把每个未决问题分配到人和日期？

若某项仍无法回答，会议记录应写清缺口与补充安排，而不是默认研发自行猜测。

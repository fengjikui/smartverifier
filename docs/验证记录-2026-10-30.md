# 2026-10-30 整图识别与拍摄等待优化

本轮按现场反馈撤下自动 CV 定位、裁剪、转正和白板生成。当前真实识别直接发送完整照片，由 VLM 返回元件、丝印、结论及是否需要重拍。`ComponentSeparator` 接口保留，未来可接入其他定位模型；管理员主动操作的图片编辑、重点区和忽略区仍保留。

## 改动边界

- 删除 OpenCV 分离实现与运行依赖，不再用锐度、纹理、背景色或固定尺寸门槛判断清晰度。文件格式、容量、解码安全限制及本机资源保护仍保留，它们不代表图像清晰度判断。
- 上传原文件保持不变；模型传输仅进行 EXIF 方向解码与完整尺寸 PNG 编码，不自动裁剪或缩小。模型服务自身的图片预处理仍由其配置决定。
- 一张照片可由 VLM 返回一个或多个元件，按元件统计不良数。输出使用 JSON Schema，并校验连续编号、位置范围、明确结论和完整结束；格式错误不生成合格结果。
- 新检测不会复用旧 CV 裁片；重判前的旧结果保留在审计中，历史已完成记录仍可查看。
- 相机打开时初始化并复用 ImageCapture，预热只查询能力，不偷拍。原照片取得后立即进入拍摄列表，缩略图在后台串行生成，不再阻塞下一张或「完成」。预览失败仍保留原照片。
- 拍摄诊断新增首次／后续快门、能力准备、曝光与缩略图耗时，便于真机区分等待发生在哪一步。

浏览器另外实测：

1. 两件照片与紧裁剪正品照片一同检测，得到 3 件、2 合格、1 不合格；紧裁剪图直接识别三行文字并合格，未被 CV 拆分。
2. 补充一张重度模糊照片，只检测新增照片。VLM 返回需要重拍，界面显示黄色提示；不良数仍为 1，存在待处理照片时不能完成。没有传统锐度逻辑参与该结论。
3. 删除这张测试照片后，恢复 3 件完成、不良数 1；可完成自主检测并查看使用完整照片的报告。自主检测仍不回填 MES。
4. 连续拍摄通过系统相机后备入口实际完成多次添加、缩略预览、删除及保存。浏览器测试环境没有目标平板摄像头，因此无法据此确认华为首张曝光延迟已经消除。

## 下一步真机复测

在华为平板已信任的 HTTPS 入口测试：打开连续取景后立即拍第一张，再连续拍 3–5 张，确认第一张等待与后续流畅度。「拍摄遇到问题？」可导出诊断，比较 `still-warmup-*`、`shutter`、`still-*`、`thumbnail-*` 的耗时。系统相机自身启动、对焦、浏览器硬件曝光延迟仍可能存在；本次只移除了应用内可提前初始化和不必要的缩略图等待。

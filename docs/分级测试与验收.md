# 分级测试与验收

更新：2026-10-29。按风险逐级执行，先验证确定性规则，再进入真实模型和设备。不把模拟测试等同于现场识别准确率。

## 测试隔离与停止条件

- 自动测试使用临时 SQLite、随机端口、测试账号、生成图片与测试 HTTP 服务，不向真实 MES 写入，不借用业务状态。
- 默认 `npm test` 强制模拟识别；真实模型只通过明确的探针运行。一次只占一个模型槽位。
- 运行构建、批量图像或真实推理前及运行中检查负载、可用内存和系统热状态；内存／热压力上升时暂停后续工作，只停止本任务进程。没有温度读数不推断温度。
- 任一层失败，先保留日志和最小复现，修复后重测相关层；涉及共享业务规则或迁移时再跑完整回归。不要在失败状态直接进入发布。
- 公司更新先备份完整状态与配置，验收后才交给业务方；详见 [Windows 一键更新](Windows一键更新.md)。

## 自动化路径

| 层级 | 要回答的问题 | 命令／入口 |
| --- | --- | --- |
| L0 静态与构建 | 类型、路由、依赖、浏览器打包是否成立 | `npm run check`、`npm run build`、`git diff --check` |
| L1 纯规则 | 提交门槛、计件、逐字差异、Schema、坐标变换是否可靠 | `npm run test:unit`；几何与区域约束另在 `reference-workflow.test.ts` |
| L2 管理与权限 | 新匹配键、版本、迁移、覆盖、草稿、分析启用、账号权限是否由后端守住 | `npm run test:admin` |
| L2 拍摄与诊断 | 曝光／编码不返回是否超时；无权限是否拒绝日志；日志是否排除照片内容 | `npm run test:camera` |
| L2 检验闭环 | 增量、重判、重拍、人工改判、不可部分提交、失败重试和旧有效结果是否正确 | `npm run test:workflow` |
| L3 实际图像与导入 | Python 确实处理像素、EXIF、自由裁剪与旋转；ZIP/RAR 路径和大小保护是否生效 | `npm run test:python`；RAR 的真实 WASM 解包在 `test:admin` 中 |
| L3 部署 | Windows 路径／UTF-8、更新备份、启动互斥、HTTPS 配置是否有回归 | `npm run test:deployment` |
| 全量离线 | 上述 Node 回归串行执行，避免测试并发放大负载 | `npm test`，另运行 `npm run test:python` |

Windows CMD 实机用例在 macOS 跳过；仓库 CI 的 Windows runner 才能验证该平台入口。模拟 GBK、路径测试和本机通过不能写成“已在 Windows 实机通过”。

## L4 浏览器交互验收

电脑管理端建议使用隔离服务，至少完成一遍：

1. 普通管理员登录，确认没有人员授权及检验任务入口；负责人专属权限由接口用例继续验证。
2. 上传 `000123 SV358.png`：文件名预填、自动分析、进度可见、丝印自动填入；无需供应商即可启用。模型不可用时可暂存，不能启用。
3. 编辑原图：滚轮以指针为中心、滑杆缩放、拖动、旋转环、角度输入、自由裁剪、取消与恢复；确认原图未覆盖。
4. 重点／忽略区不能重叠；换图或保存旋转裁剪后要求重新标记；仅查看缩放不使标记失效。读不清区域不编文字。
5. 六条测试包包含：新项、已有重复、同批两张、错误文件名、明显模糊图。确认“全部”没有勾选列，“重复项”是普通筛选，表头小型全选不代替组内单选。
6. 比较候选，只采用一张；确认覆盖。保存可用项后，其余可暂存、刷新、重新登录或重启服务继续处理。
7. 质量问题可在核对后填原因采用；列表可筛选人工强制采用，维护日志能看到人员、原因及真正变化字段。
8. 维护日志与回收站查看详情／恢复操作对应正确，不把查看详情误连到恢复。

检验端按 1280×840、840×1280 两种逻辑视口检查：登录、正品选择、任务筛选、照片总览、检测进度、详情、报告和完成。检查横向溢出、固定底栏、主按钮、详情依据默认展开、原图放大与返回后的选择位置。自动照片代理不当作真实曝光证据。

## L5 真实 VLM

预先配置 VLM 并检查模型与机器负载，串行执行：

```sh
npm run probe:reference
# 如需单独重复检验链路：
npm run probe:real
```

`probe:reference` 创建独立临时状态：真实正品分析 → 保存 → 待检照片定位裁剪 → 真实比对 → 本系统完成 → 重点／忽略区域文字分析。结果摘要存入 Git 忽略的 `var/reference-probes/`。探针结束清理临时业务库，摘要内的临时图片链接不作为永久访问地址。

必须区分三种证据：协议测试的预设返回、生成样片的真实推理、产线实拍的识别准确率。当前前两种已执行；第三种需要真实样片与人工真值，不从一张合格样例推导准确率。模型自评置信度也不是校准准确率。

目标：MatePad 11.5 S，华为浏览器，当前已知 HarmonyOS 6.1；公司使用专用 CA。

- [ ] 可信公司 HTTPS 下首次授权、后置相机、旋转屏幕和切回页面正常。
- [ ] 连拍 1／4／20 张、移除、完成、补拍、重拍替换；照片数量不重复。
- [ ] 快门后等待、缩略图出现、完成返回、上传保存全过程均有反馈，不无限等待。
- [ ] ImageCapture 失败时明确提示视频帧后备；核对实际分辨率与文字清晰度，必要时改用系统相机。
- [ ] 系统相机返回、取消、权限拒绝、浏览器后台恢复正常。
- [ ] 断网／慢网／服务重启／会话失效时照片不被误报保存，错误与重试明确。尚未提交的网页内照片刷新会丢失，当前没有离线照片持久化承诺。
- [ ] 卡住时导出拍摄诊断，按处理编号对应服务端阶段；确认是否曝光、解码、完成还是上传阶段。
- [ ] 真实元件 1／4／6 个、反光／歪斜／弱光与清晰条件，人工核对定位、裁片、文字、结论、不良数及报告。
- [ ] 公司 VLM 的地址、鉴权、Schema 与响应流实际联通；生产并发与磁盘预算单独验证。
- [ ] 真实 MES 和 IDaaS 按 [接口沟通方案](MES接口沟通方案.md) 联调，不以模拟回执代替。

没有设备或公司接口时，将对应项保持未验收；不阻碍已具备边界的本地试用交付。

# 观微 · 平板丝印检验工作台 PRD

版本：1.0 试用方案，2026-10-01。业务依据为本次现场沟通后的需求。本文的验收目标不是已经取得的测试成绩；实际交付与验证记录另见交付说明。

## 1. 执行摘要（Executive Summary）

### 问题与解决方案

来料检验员需要把一小批电子器件与正品标准对照，并把丝印检测结论、不合格件数、原始照片和逐件结构化报告写回现有 MES。现场会培训拍照，但拍摄可能中断、补拍或重拍；当前图片聊天界面需要理解裁剪和模型参数，不适合作业人员持续使用。

提供面向华为平板浏览器的任务工作台：选择任务，连续拍摄，自动定位裁剪，千问双图比对，集中复核异常，回填 MES 的丝印检测项。普通操作不要求手动放大裁剪。MES 整单最终提交由检验员在 MES 完成。

### 已确认与试用假设

| 内容 | 约定 | 状态 |
| --- | --- | --- |
| 主模型 | 沿用本机已验证的千问 27B 视觉模型，实际使用 LM Studio 已加载实例 ID | 业务已确认；运行时查验可用性 |
| 采样单位 | 一个任务对应一小批器件，一个器件不合格则该项不通过 | 已确认 |
| 图像 | 优先一张一个器件；可探索一张最多四个、互不遮挡且清晰可读 | 单件优先已确认；四件为试用约束 |
| 参考资料 | 优先经人工核对的正品图片，可附标准文字；仅文字时检查范围明确为文字 | 已确认方向 |
| 终端 | 华为平板，具体型号、HarmonyOS 与浏览器版本待定 | 待业务提供 |
| 首轮部署 | 现有 Mac 本机开发试用，后续迁到公司电脑；一次执行一个模型请求 | 用户已确认 |
| MES | 尚无接口；先约定合同，提供模拟接收及 HTTP 适配实现 | 已知依赖 |
| 工期与速度 | 无固定上线日，持续开发；希望每张几秒，按每件推理与排队分别计时 | 用户期望，需实测，不是已达成承诺 |
| 使用规模 | 初期低并发，可能几十人、最多约百人使用 | 用户估计；在线人数与同时推理数分别估算 |

### 成功指标

1. 5 名首次使用的检验员中至少 4 名，在不接受口头操作培训的情况下完成指定的三件试用任务；记录完成时间与误操作。现场用户尚未参加，不以开发者走查代替此验收。
2. 上传成功的照片在刷新、退出和服务器重启后 100% 可恢复；未传完的图片明确显示为未保存，并可重试。
3. 未检完、未复核、JSON 无效、数量不一致、缺少参考标准、任务版本冲突时，自动回填次数为 0。
4. 一件失败导致整项失败，重复上传、删除、重拍、回填重试均不改变正确的样本计数，自动化场景全部通过。
5. 用现场人工标注样本单独评估定位漏检率、关键字符错误率、误通过率、误报率、无法判定率与 P50/P90 延迟。业务风险阈值、样本量及分封装统计口径确认后，才允许扩大自动回填范围。

## 2. 用户体验与功能（User Experience & Functionality）

### 用户角色

- 检验员：用平板执行任务、拍照、继续未完成任务、确认异常与回填。
- 质量负责人：维护正品标准及版本，约定允许变化的日期/批次字段，复核误判与试用效果。
- MES 接口人：提供任务、身份、项目级保存、附件与回执能力；不需要理解模型推理细节。
- 系统维护人：配置模型、服务与 MES 连接，查看日志；模型参数不出现在日常拍摄页面。

### 主流程

进入工作台 → 确认检验员与任务 → 核对物料、标准、应检数 → 连续拍摄/相册添加 → 完成拍摄并识别 → 查看汇总及异常 → 回填丝印检测项 → MES 中人工完成整单。

试用界面明确标识“本地试用身份”和“模拟 MES”，不能把手输姓名称作 MES 登录。上线时由 MES/企业身份平台验证人员并授权任务。

### 页面与交互

1. **任务列表**：待完成任务优先，显示单号、物料、已覆盖件数和当前状态。一个“新建试用任务”入口；测试素材由用户主动加载，普通启动不自动创建演示任务。
2. **采集工作区**：顶部保持任务身份；中间为已拍照片/器件清单；底部大按钮“继续拍照”和“完成拍摄并识别”。已保存、正在上传、失败重试都有文字状态。
3. **连续拍摄**：支持安全上下文中的内嵌后置摄像头与连续快门；相机授权失败或普通局域网 HTTP 时提供系统相机、相册多选。上传串行，有进度反馈；关闭相机不会清空草稿。
4. **识别进度**：显示“正在检查第 3 / 15 件”，允许停止。已完成件保留；停止后可继续剩余识别或回到拍摄。
5. **复核**：优先展开异常件，正品和待检裁片并列，文字、差异及不确定项就近显示。正常件默认收起。人工确认通过/不合格必须填写理由，并记录身份、时间和模型原判。
6. **回填**：明确显示是“保存丝印检测项”，显示模拟/真实连接与回执。支持复制回执、下载报告包、重试失败回填；不提供 MES 整单提交按钮。

场景：明亮检验台，作业人员手持平板，需要用拇指快速操作并核对细小丝印。采用浅色背景、深石墨文字、深绿主按钮，红/琥珀仅表示失败和待处理。主要触控目标 ≥ 48 CSS px，关键正文 ≥ 16 px；横屏双列、竖屏单列，780～1440 CSS px 优先适配，同时保留手机布局。实际华为平板仍需真机验收。

### 用户故事及验收

| 编号 | 用户故事 | 完成标准 |
| --- | --- | --- |
| U01 | 作为检验员，我要进入正确任务，以免回填错单 | 任务页始终显示单号、物料、检测项、人员；同名物料不能替代任务唯一 ID |
| U02 | 我要拍一部分后离开，再继续工作 | 服务端保存已确认上传的原图和草稿；刷新/重启可恢复；失败上传明确重试 |
| U03 | 我要连续拍照，少操作界面 | 有连续快门或系统相机入口，添加后留在当前任务；无需逐张进入裁剪编辑器 |
| U04 | 我要重拍、删除错误照片 | 上传中/识别中有互斥提示；删除保留审计，编号不复用；替换时旧图不再计入样本总数 |
| U05 | 我要系统自动找到器件 | 自动生成保留引脚及边距的裁片；定位失败、数量异常和模糊有提示；不把未检测到当作合格 |
| U06 | 我要一次识别整批 | 逐件请求主模型，每件结果关联来源照片与标准版本；完成后由程序汇总，不让模型自由生成批次件数 |
| U07 | 我要快速确认不合格和存疑项 | 双图、读字结果与差异同屏；所有异常需明确复核；错误、超时、不可读不自动通过 |
| U08 | 我要保存结果到 MES | 应检数=有效器件数，全部完成且异常已复核后允许回填；原图+JSON+汇总有同一回执 |
| U09 | 我要处理上传失败 | 相同报告重试使用同一幂等键；回执丢失可查询；未拿到确认不显示“已回填” |
| U10 | 作为负责人，我要有可追溯标准 | 标准图片、人工核对文字、允许差异规则、审批人和版本被任务快照引用 |

### 状态与计数规则

- 作业状态：采集中 → 识别中 → 待复核/可回填 → 回填中 → 已回填/回填失败。取消或服务重启后保留完成项，未完成项可重试。
- 器件结果：`PASS`、`FAIL`、`REVIEW`；未识别为 `PENDING`，执行异常为 `ERROR`。后两类都不能进入通过状态。
- 模型给出 `FAIL` 或 `REVIEW`，以及图像定位/质量告警，都需要人工处理。复核保留原判、最终判定和理由。
- 不合格数量按不同器件 ID 统计，同一器件多个差异只计 1 件。照片数量单独统计。
- 有任一最终 `FAIL` 时整项为 `FAIL`；没有失败但存在未完成/待复核/数量不符时，整项为 `INCOMPLETE`；只有全部完成且数量一致才为 `PASS`。
- 同文件重复上传用 SHA-256 拦截，网络重试有请求 ID。不同照片拍了同一个实物无法单靠算法可靠去重，应重拍替换或由操作员核对实物数量，不宣称已解决物理身份识别。
- 照片增删、替换、裁片旋转或标准改变会使相关结果失效；回填基于不可变报告版本。回填执行期间冻结内容变更，成功后保留历史，新修订需明确重新打开并更新项目版本。
- “通过后自动回填”为显式选项，默认关闭；仅全部明确通过、无图像告警、数量完整时触发。不会绕过异常复核或代为提交整单。

### 首轮不做（Non-Goals）

不做真伪鉴定或概率打分、不替代电性检测、不自动提交 MES 整单、不直接写 MES 数据库、不伪造员工身份、不假定华为平板已完成真机兼容、不保证任意背景和封装都能自动定位。保留既有图像聊天和自主裁剪 Agent，主界面不再要求操作员手动裁剪。

## 3. AI 系统要求（AI System Requirements）

### 工具及模型

- OpenCV 定位模块：在缩小的检测预览上找轮廓与旋转框，在原始分辨率图上裁片，保持比例、留边，记录坐标和旋转角。明亮单色背景、分离摆放的器件为首轮支持条件。
- 矩形定位不是精细分割，不能保证文字朝上；允许异常时旋转 90°/重新拍摄，避免为了方正而任意透视拉伸。原图不覆盖，颜色不做生成式修复。
- 一张最多四件；超出上限、物体接触边界、目标过小、未定位或低清晰度都会阻止自动回填。阈值是工程告警，不是准确率。
- 千问：每件输入正品裁片（若有）、待检裁片、经核对的标准文字、允许变化规则和固定指令。关闭思考，限制输出，串行推理。模型服务不可用时保留草稿，不产生假结果。
- 仅文字标准时报告 `comparison_scope=text_only`，不得声称外形、颜色或图案已与正品一致。
- 图片里的文字只作为数据，不能改变流程、工具调用或系统指令。模型不负责决定任务身份、回填地址、计数或操作者。
- 输出经 Pydantic/JSON Schema 校验；字段缺失、非法枚举、空结论、截断、额外工具命令均进入执行失败/待复核。原始模型输出留存。

### 每件结构化结果

包含器件 ID、照片 ID、标准 ID/版本、模型标识、比较范围、读出的逐行文字、外观特征、可见差异、无法确认项、建议结论和证据说明。差异包含类别、待检观察、标准观察和文字描述；不生成伪精确的“假货概率”。坐标若由模型给出仅供提示，照片与裁片的几何坐标由实际图像处理记录。

### 评估方案

1. 几何测试：单件、倾斜、四件、边缘截断、无器件、接触、低清晰度；核对定位数、完整引脚覆盖、坐标回溯及编号稳定性。
2. 合成照片：标准、字符改变、多件混合。人工记录图片实际内容和预期差异，不用提示词中的期望内容充当真值。
3. 模型试用：实际 LM Studio 双图请求，记录模型原文、输入、耗时和是否与人工观察一致；并列展示成功与失败，避免只挑成功样本。
4. 状态与接口测试：中断恢复、部分失败、取消、重复请求、越权访问、数量不符、人工复核、回填超时、回执恢复、版本冲突、附件完整性。
5. 真机与现场：具体华为设备到位后验证摄像头、相册、横竖屏、睡眠恢复、断网、HTTPS、中文输入；采集真实不同封装与光照样本后再定误通过率门槛。

## 4. 技术规格（Technical Specifications）

### 架构与数据流

平板 React 网页 → 同源 Node 局域网入口 → FastAPI → SQLite 任务/审计/回填记录 + 本机图片目录 → OpenCV → 已加载的 LM Studio → JSON 校验和汇总 → MES 适配器。

沿用仓库 React/Vite 与 Python 工具链；首次运行不加载假检验记录。原图上传保存成功后才提示已保存。原图、方向规范化图、裁片、编号图分别存储，保留 SHA-256、尺寸及派生关系。SQLite 单机事务用于首轮任务持久化；并发生产服务扩展到服务端数据库属于后续部署工作。

### 容量与响应时间

上传/保存与识别分开；识别最多排队 100 个任务，当前电脑一次执行一个请求，显示排队位置及每件耗时。几十到百人在线不代表可以同时运行百路 27B 模型；若单件约 11 秒，单路理想吞吐仅约 5 件/分钟，突发排队会明显增加等待。正式部署需要测量同时活跃任务、每任务器件数、峰值到达率，再决定服务端数据库、持久队列、推理工作进程与多实例资源。本次不会以单机串行实现冒称百人并发验收通过。

### MES 集成

首选：HTTPS REST，附件独立上传，检测项结果以 JSON 幂等保存，返回可查询回执。具体字段、端点、状态码和样例见《MES接口协作方案》。项目级保存不触发整单提交，任务版本冲突不自动覆盖其他项目。

首轮提供本地模拟接收器与独立 HTTP 接收示例、生产形状的 HTTP 客户端适配器、JSON/ZIP 导出。模拟结果明确标识。接口未确认前不接真实 MES；不得把本地回执描述为 MES 已保存。

备选为受控文件交换（JSON+原图+manifest ZIP，收件回执）或由 MES 轮询我们的待交付结果。优先推动首选合同，减少双方同时实现三套接口。浏览器自动填表仅作临时应急方案讨论，不作为主集成路线。

### 身份、网络和隐私

- 局域网配对码和 HttpOnly 会话隔离试用数据；这不是企业检验员认证。真实接入需要 MES/企业 SSO 返回稳定员工 ID、任务权限及必要的代理操作授权，禁止让平板填写 MES 服务密码。
- MES 服务凭证只在服务端环境配置，前端不接触；真实外部传输必须使用 HTTPS，服务端验证证书。
- 使用 MES 的任务 ID、检测项目 ID、物料与标准版本进行关联，不能以电脑当前打开的页面或姓名相同作为绑定依据。
- 同源 API 校验、服务端归属检查、上传类型/尺寸限制、结构化输出校验、回填幂等、审计和原图不覆盖是首轮要求。
- 连续 `getUserMedia` 相机要求安全上下文。局域网正式试用配置 HTTPS；HTTP 提供系统相机/相册后备。不能保证尚未指定的 HarmonyOS 浏览器支持所有拍摄能力。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- 保留期、备份、访问审计、离职回收、生产角色权限由业务/IT 确认。首轮不自动删除证据，也不上传业务图片到外部 AI 服务；生图仅生成虚构测试素材。

## 5. 风险与路线图（Risks & Roadmap）

### 分期

- **MVP 本次**：中文需求与接口合同，单机平板工作台，草稿/续拍/自动裁剪，真实模型比对，人工复核，批次汇总，模拟回填与可替换 HTTP 适配器，测试素材及验收记录。
- **v1.1 现场试点**：真实平板、HTTPS/企业身份、MES 项目级暂存联调、真实器件评估、定位阈值与封装范围确定。
- **v2.0 扩展**：轻量检测模型、更多封装与复杂背景、标准审批/版本治理、多人并发、集中数据库、监控与企业备份。依据试点评估决定，不默认采购算力。

### 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 普通轮廓算法把托盘、阴影识别为器件 | 限定摆放背景与最多四件；定位/数量异常进入处理，不以“没找到”通过；评估后决定是否训练轻量检测器 |
| 参考照片批号与来料合法不同 | 标准维护明确可变字段，默认差异待核对；不能自行忽略任意数字 |
| 比对把光照差异当成颜色缺陷 | 要求描述证据与不确定性；避免未经校准的绝对颜色结论 |
| 网络断开时不知道 MES 是否已保存 | 幂等键与回执查询；保留本地快照，不盲目重复创建 |
| MES 页面最后保存覆盖已回填项 | 接口人确认独立项目保存与版本控制，真实联调前作为阻断项 |
| 热压力、内存或模型队列拥塞 | 一次一个请求，推理前及期间监测，可取消，超时保留草稿；不终止用户其他进程 |
| 过度相信合成图片的识别成绩 | 合成、几何和真实现场测试分开记载，不对外宣称生产准确率 |

### 等待对方确认

具体平板/浏览器；单件/多件正式规则；应检数来源及补检流程；检验员/复核员权限；标准维护人及有效期；合法可变字段；MES 暂存和最终提交关系；项目级覆盖策略；附件限额/留存；并发、响应时间与上线日期。未回答项不阻止本地试用实现，但相应能力不得被标为已生产验收。


## 2026-10-03 平板交互落地补充

主流程更新为：设备配对（首次）→ 本地试用登录 → 任务筛选与选择 → 核对物料/应检数量/标准 → 连续拍照 → 照片确认 → 批量识别进度 → 异常双图复核 → 提交丝印检测项 → 回执与留档。

- 任务筛选独立成页；开始/截止日期、任务状态、单号/物料关键词，筛选条件记住到下次进入。当前日期字段是任务创建日期，正式进货/送检日期字段待 MES 确认。
- 华为系红色作为动作色，主操作目标至少 48 px；桌面横屏与平板竖屏均可用。聊天、模型参数不进入日常检验主流程。
- 账号密码是本地试用能力，不模拟已接通企业认证；不同账号隔离，同账号可跨配对设备续做。新建账号承接当前设备旧试用资料时保留历史任务快照。
- 拍摄、识别、回填是三个独立阶段。确认页应检数量一致、无定位阻断才可开始批次识别；后台接口保留续跑部分未完成件能力。模型 FAIL 必须人工复核后才计入正式不合格数。
- 原图不覆盖；框与编号写入单独的展示图，编号在原图外两侧留白中。模型读取无编号裁片。轮廓校正解决几何倾斜，不保证文字天然朝上，保留 90° 修正和重新待检。
- 登录过期、暂时网络失败时未确认保存照片保留在当前页面内存；支持原地登录、同请求重试。关闭浏览器或系统回收页面不保证未上传照片保留，因此明确提示并阻止常规离开。
- 保存后展示回执，可查看逐件结果及下载报告；不能编辑已经保存的证据。真实 MES 整单提交仍由人处理。

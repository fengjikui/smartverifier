# 试用演示基线与缺口清单

2026-10-20，按当前根目录应用核对。目标是先交付稳定试用与演示版本，暂停模型缓存、白板吞吐及小模型优化。

## 当前能完成什么

当前是**真实识别已接入的试用版**，尚不是公司系统联通后的正式投用版。

平板正常流程已覆盖：进入本地试用→选任务→连续拍照→保存及继续添加、替换、移除照片→OpenCV定位裁剪与小角度转正→正品图与单个元件裁片交给VLM→进度与结果→可选人工改判→逐字差异与完整报告→模拟MES回填及失败重试。增量检测、修改说明重判、旧结果保留、不能部分提交等规则已有测试。

VLM连接统一为服务端配置的地址、模型和协议；保留本机LM Studio，新增公司兼容HTTP接口。新调用标记VLM来源，旧LM Studio识别记录继续作为真实模型结果显示，不会误标为预设。白板当前只展示／实验，正常业务仍按元件串行处理。

## 建议的实施顺序

1. **本次：固定真实逐件识别基线，统一VLM配置和HTTP适配，保留可回退检查点。**
2. **已实现：正品录入、批量导入与任务只读展示；下一步整理真实资料试录并接入 MES 任务。** 见《正品管理试用与数据维护》。
3. 用真实照片和平板完成一轮验收，修复实际影响操作和判断的问题。
4. 对接公司VLM、IDaaS、MES接口；如接口尚未就绪，演示清楚标记模拟部分。
5. 演示稳定后，再推进管理员增强功能、容量、白板批量识别及模型性能优化。

验收至少覆盖：正确件合格、明确差异件不合格；低质量图片不产生假结论；补拍只增量识别；现场说明重判及人工改判可追溯；有未完成照片时不能提交；回填失败明确提示且旧有效结果保留。

配置步骤见[VLM服务配置与迁移](VLM配置.md)。企业接口待确认项见[业务与MES待确认事项](待对接事项.md)。

## 管理员账号密码与协作录入（2026-10-19）

当前管理员暂不接公司 IDaaS，支持部署人员用终端交互命令配置具名账号、显示姓名及 scrypt 密码哈希。`SV_ADMIN_LOCAL_ONLY` 默认为 true，使用 `npm run admin:access -- lan/local` 修改开放范围，重启服务应用；只提供账号文件不会隐式开放远程。未配置具名账号不能开放默认试用密码，账号文件损坏或开关错误会阻止启动。

验证：TypeScript 和构建通过，Node 46 项回归通过，包含新增5项管理员配置、访问限制、会话撤销、旧表升级及 HTTP 录入留痕测试。以本机实际局域网 IP（非回环地址）进行隔离 HTTP 验证：开放后登录／读取200；改为仅本机并重启，旧远程会话401、远程登录403、本机登录200。浏览器使用独立状态目录，验证错误密码后重试、具名账号登录、保存草稿和维护日志人员信息；修复了登录成功后残留上次错误提示的问题。

实际运行了终端账号配置提示，确认密码不回显，并在确认密码前取消，未修改业务机账号。助手的哈希保存、多人配置、重复账号保护及配置保留使用临时目录验证。真实服务仍保持仅本机默认试用配置，未替用户设置真实密码或开放权限。更新前保存数据库副本；服务重启后，任务、轮次、标准、版本与业务审计的逐表校验值一致。验证记录保存在被 Git 忽略的 `var/admin-access-verification`，不含明文业务账号密码；本轮不运行真实模型推理。

协作录入前，由部署人员设置账号后按《部署说明》5.1节开放，并将服务器的局域网管理地址提供给录入人员；模型调试限制不随管理员开关解除。迁移时另行保留 `.env.local` 及 `var/config` 的账号文件，业务数据仍在原状态目录。


## 人员与权限管理（2026-10-20）

已区分系统负责人和正品管理员。新增负责人专属页面 `/inspections/marking/admin/users`：新增普通管理员、停用／启用、修改显示姓名、重置密码和授权日志；普通管理员没有侧栏入口，直达只显示无权限，名单和全部授权接口均由服务端校验负责人角色。网页不能创建或提升负责人，不能停用、改名或重置负责人密码；账号名称 admin 不代表负责人。

部署人员使用 `npm run admin:owner` 初始化或增设备份负责人，`npm run admin:owner -- --replace` 恢复同一负责人，重启生效。网页人员变更立即生效并撤销旧会话。人员、状态、密码哈希和授权日志保存在 SQLite，服务器私有账号配置用于初始化和离线恢复。旧账号按普通管理员导入，不自动提权；不变配置不会在重启时覆盖网页停用或改密，服务器更新普通账号密码也保留停用状态。账号不能永久删除或复用，历史资料和原操作人留存。

验证：TypeScript、前端构建与 Node 51 项回归通过。新增测试覆盖角色与页面路径、默认试用账号无授权能力、越权查询／写入拒绝、伪造角色拒绝、负责人保护、停用与凭证即时失效、跨重启状态和密码保留、乐观版本冲突、日志不含凭证、账号／会话／审计的事务回滚、等待密码计算时退出导致授权取消，以及离线负责人恢复。期间发现并修复 Node 原生 TypeScript 不支持参数属性的运行问题。

浏览器使用独立状态目录与合成账号，亲自完成：负责人新增普通管理员；普通管理员入口隐藏和直达拦截；普通管理员录入草稿与留痕；负责人停用、已停用账号登录失败、按状态筛选、启用、菜单重置表单及授权日志检查。修复了切换账号后遗留提示和行菜单文字溢出。密码重置的实际保存和会话撤销由 HTTP 集成测试覆盖，浏览器只打开表单并取消，不修改真实密码。

真实服务升级前保存数据库副本，升级后原有任务、轮次、标准、版本、维护日志及检验业务审计的逐表校验一致。没有往业务库添加测试负责人、录入账号或草稿，没有替用户设置正式密码，访问仍保持仅本机；没有进行真实模型推理。运行证据及截图位于被 Git 忽略的 `var/people-roles-verification`。操作与迁移细节见[人员与权限](人员与权限.md)。

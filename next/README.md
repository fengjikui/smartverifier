## 协作方式

1. 默认每轮集中讨论一个主题；用户也可按总清单编号一次回复多项，无需一次答完全部问题。
2. 先说明当前理解，再给出简短建议，由用户补充或纠正。
3. 把结论区分为「已确认」「建议」「待确认」；未明确接受的建议不写成已确认需求。
4. 每轮有新结论时，将结论与确认日期补充到对应方案位置；改变原结论时保留变更说明。
5. 先统一业务需求，再设计操作流程与界面，之后讨论数据与接口，最后分段实现和试用。
6. 每次实现只交付一个可试用的小闭环，说明本次变更、验证结果和下一步。
7. 所有设计从现场检验员方便使用出发：优先在平板完成操作，常用内容尽量点选，减少打字，并考虑便捷语音补充。
8. 对交互与实现细节，助手先采用合理默认方案并记入设计备忘，避免逐项停下来确认；交流优先聚焦会影响业务规则、范围和职责边界的问题。
9. 当前主流程作为第一阶段基础；后续新功能随时登记，区分首轮必需与后续增强，不要求全部想完才推进设计和实现。
10. 已授权在可独立回退的重要节点完成验证后自动创建本地 Git 提交；相关小修改可合并，提交说明使用中文，交付时附提交编号。具体约定见根目录 `AGENTS.md`。

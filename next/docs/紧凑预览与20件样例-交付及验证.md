# 紧凑预览与 20 件样例

日期：2026-10-17。

## 直接试用

- [20 张照片，每张 1 件](http://127.0.0.1:5190/tablet-preview?demo=photos)：切换「紧凑预览」，对照标准大小与紧凑大小，试试滑动、异常筛选和照片详情。
- [单张照片包含 20 件](http://127.0.0.1:5190/tablet-preview?demo=board)：点开照片后，查看 20 个元件的状态按钮；再打开报告，看编号和逐件摘要。

两项都是独立且明确命名的本地流程样例，预设为 16 件合格、4 件不合格。第二项含 3 件低把握但有明确合格结论的元件，复核仍可选。它们不代表真实模型批量识别的准确率或速度。

## 交互调整

新任务默认仍为原来的标准预览，不根据数量自动改变。照片多时，由检验员一键开启紧凑预览；当前任务的选择会保留，返回总览和刷新后不必重选，另一项新任务默认使用标准预览。切换时尽量保留当前正在看的照片位置。

| 逻辑网页宽度 | 标准预览 | 紧凑预览 |
| --- | --- | --- |
| 横屏 1280 px | 每行 3 张 | 每行 5 张 |
| 竖屏 840 px | 每行 3 张 | 每行 4 张 |
| 手机 371～600 px | 每行 2 张 | 每行 3 张 |
| 更窄的手机 | 每行 2 张 | 每行 2 张 |

缩小的是总览卡片，详情对照不缩小。缩略图仍显示进度、合格／不合格和建议复核；按钮保留文字或可访问名称。手机紧凑模式将「替换照片」改为图标，点击范围保持至少 44 CSS px。

10 月 17 日的详情按钮曾采用横屏两行各 10 个、竖屏 8＋8＋4，并显示状态符号。10 月 18 日按反馈精简为 44×44 CSS px 的纯数字按钮，按可用宽度换行；绿色表示合格，红色表示不合格，灰色表示待检测，当前项加边框。低把握提示移至具体结论旁。详情统一支持本轮跨照片切换，见[最新交付记录](页面信息层级与统一元件详情-交付及验证.md)。

报告中的 20 件样例保留原图及编号，编号放在样例留白内。当前逐件查看已统一到照片详情；完整报告上下连续阅读，默认收起导航，按需定位元件。Markdown 下载仍包含全部逐件结果。旧版本的折叠和双模式记录仅供回溯。

## 样例与服务

新增 `twenty` 单图样例和 `POST /api/rounds/:id/sample-set` 的 20 张照片样例。后者一次保存并使用 `clientId` 去重，不按相同图像哈希合并元件。添加过程中出错或版本冲突，会清理此次产生的文件，避免留下部分照片记录。

`fixtures/inspection/twenty-components.png` 由既有虚构样片程序拼接；来源哈希、坐标和预设结果在旁边的 JSON 中保存。该图片与真实采集照片、真实推理实验分开使用。

独立演示任务通过下列命令显式准备，普通启动不会自动向用户任务里添加样例：

```sh
# 停止本地试用服务，确认没有检测／回填进行中后执行
node next/scripts/prepare-twenty-demo.ts
npm run start:next
```

脚本使用 `SV_NEXT_STATE_DIR` 或默认 `outputs/next-state`，创建 `DEMO20PHOTOS`、`DEMO20BOARD`；已有演示记录会保留，不覆盖用户改动。本次准备前后，原有两轮检验记录的持久化内容逐字一致。

# 正品管理试用与数据维护

2026-10-18。管理端沿用已确认的 Figma 设计，电脑使用为主，兼容平板浏览器。

## 进入与身份

启动当前新版服务后打开 `http://127.0.0.1:5190/admin`，不需要从检验工作台进入。

首轮试用账号：`admin`，密码：`admin123`。这是明确标注的本机开发身份，日志记录为“试用管理员 / ADMIN-TRIAL”，不代表已验证公司人员。当前默认只允许服务器本机登录管理员，不能把公开的试用密码用于正式上线。

检验员和管理员使用独立会话，普通检验会话不能修改正品库。浏览器刷新会保留管理员会话，8 小时后需重新登录。收到公司 IDaaS 方案后，替换认证入口并将可信人员标识映射到管理员授权；不需要重做标准、导入、任务关联与日志业务。

## 常用录入方式

1. 在“正品标准”点击“新增标准”。
2. 填物料编号、供应商，添加一张清晰的正品图。物料名称和检测说明选填。
3. 检测说明写检查重点与允许变化内容，例如日期码／批次码允许变化，型号和 Logo 必须一致。
4. 点击“保存标准”立即启用；“保存并继续新增”继续录入下一条，保留供应商；资料不完整时可“保存草稿”。

物料编号和供应商共同唯一，去首尾空白、作 Unicode NFC 规范化，保留前导零，区分大小写。不建议自行缩写供应商名称，须与任务一致。重复保存会提示编辑原记录，不会覆盖。

正品图片保留原始字节及 EXIF，不压缩替代；列表使用 192px 以内的独立缩略图。允许静态 JPG、PNG、WebP，单图最多 20MB / 4000 万像素。图片不依赖外部网址。

“更多选项”中可填写正品丝印文字，每行一条，用于逐字差异展示；不填也可以依据正品图检测，系统不会将“未录入文字”当作差异。每组标准目前一张图。

未保存输入会在当前浏览器恢复，主动离开会提醒；保存失败保留字段。恢复缓存只是辅助，重要资料请及时保存到服务端。更换浏览器、清除浏览器数据或更换地址不会迁移本地未保存输入。

## 搜索、修改与回收站

列表按物料编号、供应商、物料名称查询，可筛选启用／草稿，服务端每页最多 50 条（界面默认 25 条），不会一次加载 15000 张图。

点击物料编号查看详情；“编辑”直接修改；更多菜单支持复制新增或移入回收站。复制保留图片和说明，物料编号需重新填写。回收站“查看详情”只查看，“恢复”单独确认，不混用两个动作。

每次保存、移入回收站及恢复都生成新版本并记录操作人、时间、变更前后内容。多人同时编辑，后保存的人会收到版本冲突，不会覆盖别人刚保存的内容。恢复时如已有相同组合，会提示先处理重复记录。

标准修改、停用为草稿或移入回收站，只影响后续开始的检测。已经开始的轮次和历史报告继续使用创建轮次时保存的标准快照；原图不会随标准删除而消失。

## Excel、JSON 和 ZIP 导入

“批量导入”提供 Excel、JSON、含图片的 ZIP 示例与填写说明下载。Excel 模板的“标准清单”当前为空，示例只供参考；ZIP 示例的物料与图片为虚构资料，请勿作为业务正品。

支持两种上传：

- 一份 Excel / JSON 清单，再选择清单所用的多张图片。图片按路径或唯一文件名匹配，不同目录的同名文件建议先重命名。
- 一个完整 ZIP，内含恰好一份 Excel 或 JSON 清单及相对路径指向的图片。不要上传含多个格式清单的“模板资料总包”。

Excel 必填列为物料编号、供应商名称、正品图片路径；检测说明选填。物料编号必须是文本类型，数字类型和公式会明确提示修正，防止前导零损失。可额外加入物料名称、正品丝印文字两列。

JSON 使用 `schemaVersion: "1.0"` 和 `records`，每条字段为 `materialCode`、`supplierName`、`imagePath`、`description`，可选 `name`、`markingText` 或 `markingLines`。

每批最多 2000 条、上传总计 200MB，建议先用 2–5 条试导，再按 500 条一批。ZIP 解压总计最多 500MB、5000 个条目，不接受危险路径、符号链接、加密包或多个清单。预检为后台串行图片校验，不调用 VLM；期间可离开管理页，再回来查看。

预检显示可新增、已有组合跳过、错误条目。任何错误均阻止整批写入，修正后重新上传；不会部分导入。确认时再次检查并发新增产生的重复项，仍按跳过处理。重复确认同一导入单返回原回执，不会重复新增。导入数据按条留痕，另有整批操作日志。

## MES 任务与正品绑定

检验任务由 MES 提供，本系统不新增、修改或删除任务。管理端“检验任务”仅用于查看、关键词查询、刷新列表，以及检查正品标准是否关联。MES 接通前，启用的标准会自动提供对应模拟任务，供真实识别试用。

系统依据 MES 任务里的物料编号＋供应商，自动匹配已启用标准。缺少基准时，由管理员补齐正品库，检验员不能自行添加正品或修改任务信息。已开始的检测保留当时的标准快照。

在任务行点击“打开检验”进入现有平板工作台，检验员也可从平板任务列表选择。当前 MES 接口尚未接通，页面明确标注演示数据；“刷新列表”刷新本系统的模拟任务来源，不表示已向真实 MES 同步。原先试用创建的记录保留为只读历史试用任务，不再提供维护入口。

## 部署、备份与迁移

服务端需要 Node.js 24 和已有项目依赖，以及现有 Python 图像环境：

```sh
uv pip install --python agent-tools/image-focus/.venv/bin/python -r next/server/vision/requirements.txt
npm run build:next
npm run start:next:real
```

可通过 `SV_VISION_PYTHON` 指向其他机器的 Python；模型服务继续使用 `SV_VLM_ENDPOINT` 等配置。只录入资料不需要启动模型推理，普通 `npm run start:next` 也能维护标准。

资料默认保存到 `outputs/next-state/inspection.sqlite` 和同目录 `files/`，另有检测报告等文件；可用 `SV_NEXT_STATE_DIR` 指定独立数据目录。Git 只管理代码和模板，**不会自动备份录入数据**。

迁移和离线备份：先正常停止本系统服务，完整复制状态目录（包括 SQLite、可能存在的 WAL/SHM 文件、files 和报告），在目标机用同一状态目录启动。不要只复制 SQLite 而遗漏原图，也不要覆盖目标机已有数据。先用复制目录恢复一次，确认标准数量、详情原图和任务可打开，再交付业务人员。

预检失败、取消和更换图片可能留下未被标准引用的图片；当前不自动清除，以免破坏历史快照。正式使用前需补充备份轮换、未引用文件保留策略和磁盘告警；真实图片规模应按平均原图大小估算，15000 种物料不能只按数据库大小预算。

公司 IDaaS、MES、HTTPS 部署和真实平板照片仍待联调。本轮不声称完成企业正式上线或 100 人同时操作的容量验收。

## 不依赖 MES 任务的先行试用

可直接从检验端“自主检测”按物料和供应商选择正品，上传照片进行真实识别，不需要模拟或真实 MES 单号。正品描述可以留空。结果页展示结论与不良数量，检验员手工填写电脑 MES；提交按钮禁用，不上传附件。详见《自主检测与模拟 MES 试用说明》。

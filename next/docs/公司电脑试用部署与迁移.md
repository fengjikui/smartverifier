# 公司电脑试用部署与迁移

2026-10-18。适用于当前 `codex/tablet-inspection-workbench` 分支。请从该分支部署，`main` 不一定包含这些功能。

## 1. 本次交付与运行方式

业务服务运行在一台公司电脑上，平板浏览器访问它；业务服务通过配置的地址调用 VLM。平板不安装 Python、不保存模型密钥。公司已经有 VLM 服务时，业务电脑不需要显卡，也不需要下载模型权重。

当前可以：正品标准维护／导入 → 按物料与供应商选择正品 → 自主检测 → 自动定位、裁片、逐件真实比对 → 查看结论与不良数 → 人工填写电脑 MES。标准描述可留空；自主检测不上传 MES 附件，提交 MES 按钮禁用。模拟任务路径保留用于演练，不代表公司 MES 已接通。

公司 IDaaS / MES 尚未接通，检验员使用同一明确标注的试用身份，不可当作真实人员隔离或正式上线版本。首轮先使用少量清晰样品；目前定位器适合绿色防静电台面、相互分离的深色封装。日常识别逐件串行，尚未进行多人容量验收。

## 2. 准备环境与代码

安装 Git、Node.js **24.x**、Python **3.12**。当前开发验证为 macOS + Node 24.14.0；下面提供 Windows PowerShell 与 macOS/Linux 命令，**Windows 实机及公司模型尚待到场验证**。已修正 Windows 没有 `os.getloadavg` 的运行阻断。

建议业务电脑有 16GB 或以上内存；图像工作器要求当时可用内存至少 8GiB，CPU 高负载时会暂停。本机还运行大模型时，内存需求另计，不能按业务服务容量估算。为正品原图、检验照片、派生图和备份预留磁盘空间。

```sh
git clone --branch codex/tablet-inspection-workbench --single-branch https://github.com/fengjikui/smartverifier.git
cd smartverifier
node --version
npm ci --include=dev
```

仓库访问需要相应权限；也可将本次 Git 提交导出的源码 ZIP 拷到公司后解压。从项目根目录执行本文命令。使用 `npm ci` 按锁文件安装，先不要升级依赖。首次安装需要能访问 npm 和 Python 包源，内网受限时由 IT 配置公司镜像。

### Windows PowerShell

```powershell
py -3.12 -m venv next/.venv
& ./next/.venv/Scripts/python.exe -m pip install -r next/server/vision/requirements.txt
& ./next/.venv/Scripts/python.exe -c "import PIL, cv2, lmstudio, psutil, httpx, openpyxl, defusedxml; print('Python依赖就绪')"
# .env.next.local 不存在时才复制；已存在时编辑原文件。
if (!(Test-Path .env.next.local)) { Copy-Item next/config/company-trial.env.example .env.next.local }
```

### macOS / Linux

```sh
python3.12 -m venv next/.venv
./next/.venv/bin/python -m pip install -r next/server/vision/requirements.txt
./next/.venv/bin/python -c "import PIL, cv2, lmstudio, psutil, httpx, openpyxl, defusedxml; print('Python依赖就绪')"
# 已有配置时不覆盖。
test -f .env.next.local || cp next/config/company-trial.env.example .env.next.local
```

无需复制开发电脑上的 `.venv` 或 `node_modules`。离线部署必须在相同目标系统、CPU 架构和 Python 版本准备依赖包，不能把 macOS 的二进制依赖直接搬到 Windows；本文不声称源码 ZIP 含离线依赖或模型。

## 3. 编辑配置与连接模型

打开项目根目录 `.env.next.local`，参照 [公司试用配置模板](../config/company-trial.env.example)：

| 项目 | 如何填写 |
| --- | --- |
| `SV_VISION_PYTHON` | Windows：`./next/.venv/Scripts/python.exe`；macOS/Linux：`./next/.venv/bin/python` |
| `SV_NEXT_STATE_DIR` | 默认 `./outputs/next-state`；也可用独立绝对目录，如 `D:/SmartVerifier/data` |
| `SV_NEXT_HOST` / `SV_NEXT_PORT` | 局域网试用为 `0.0.0.0` / `5190`；仅反代访问时可改为 `127.0.0.1` |
| `SV_VLM_PROVIDER` | 公司 HTTP 服务填写 `openai-compatible` |
| `SV_VLM_ENDPOINT` | 实际 VLM 基础地址，通常含 `/v1`；亦可填写完整 `/chat/completions` 地址 |
| `SV_VLM_MODEL` | 服务对外暴露的模型名，须由模型管理员确认 |
| `SV_VLM_API_KEY` | 如果服务有认证，填对应密钥；无认证留空 |
| `SV_VLM_TIMEOUT_SECONDS` | 首轮建议 90 秒；允许 5～180 秒 |
| `SV_MODEL_DEBUG` | 内网试用保持 `0`；本机需要查看模型输入输出时才改成 `1` |

路径建议使用正斜杠，即使在 Windows 上也填写 `D:/...`。含空格的值用双引号包住。配置由 `npm run start:next:real` 读取；修改后重启业务服务。

VLM 服务需要支持图片 Data URL、流式 Chat Completions 和 `response_format` JSON Schema。健康检查仅说明本系统启用了该适配器，**不代表已探测模型连通性**；实际上传一张照片识别，才完成端到端确认。不支持 Schema、超时或返回错误时，系统不会悄悄改用预设结果。详细协议见 [VLM 配置说明](VLM服务配置与迁移.md)。

如果公司电脑也使用 LM Studio，可优先使用其兼容 HTTP 服务，实际模型标识及 Schema 支持仍需验证。本机 SDK 方式设为 `lmstudio`，需另填对应模型的 `SV_VLM_TEMPLATE`，见 [本机说明](本机真实识别试用与部署.md)。不要复制本机 `hr-qwen` 别名或 macOS MLX 权重路径当作公司电脑配置。自动加载模型、模型下载和公司服务部署均不由本项目完成。

`.env.next.local`、业务数据与密钥不提交 Git。模型 API 地址属于服务器配置，平板只填写业务系统地址。

## 4. 构建、启动与地址

```sh
npm run check:next
npm run build:next
npm run start:next:real
```

保持终端运行，停止时在该终端按 `Ctrl+C`；关闭终端、电脑休眠或关机后服务会停止。首轮前台试用即可，长期运行由 IT 使用系统服务管理器，工作目录设为仓库根目录，同一数据目录仅启动一个业务服务进程。

| 用途 | 本机地址 |
| --- | --- |
| 自主检测 | `http://127.0.0.1:5190/inspections/marking` |
| 正品管理 | `http://127.0.0.1:5190/inspections/marking/admin/standards` |
| 电脑平板模拟器 | `http://127.0.0.1:5190/inspections/marking/preview/tablet` |
| 模拟 MES 任务 | `http://127.0.0.1:5190/inspections/marking?entry=tasks` |
| 健康检查 | `http://127.0.0.1:5190/api/v1/inspections/marking/health` |

Windows 可用 `Invoke-RestMethod` 请求健康地址，macOS/Linux 可用 `curl --fail`。预期 `ok:true`、`recognition.mode:vlm`；`mode:mock` 指企业集成仍为模拟。

旧的 `/admin`、`/tablet-preview`、`/debug/model`、根级 `/assets/...` 和 `/api/...` **已停用，返回 404，不再跳转**。请使用上表的新地址；只在规范地址末尾斜杠等场景做规范化跳转。其他早期演示工程的 `npm run dev` / `start:lan` 不是本次部署入口。

## 5. 让平板访问

让平板和业务电脑位于可互访的公司网络。将地址里的 `127.0.0.1` 换成业务电脑的局域网 IP，例如 `http://192.168.10.20:5190/inspections/marking`；IP 为示例，不能照抄。平板里的 `localhost` 指平板自身。由 IT 仅向试用网段开放 TCP 5190，确认无线网络没有客户端隔离。

当前“拍照”使用文件输入的 `capture="environment"`，不是网页实时摄像头流。不同浏览器可能弹系统相机或文件选择器，必须在实际华为平板验证；相册上传始终作为试用路径。该属性的平台差异见 [MDN capture 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)。如果后续改成 `getUserMedia` 实时拍摄，它要求安全上下文，见 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia#security)。

建议公司提供带受信任证书的内网 HTTPS 域名。反向代理应完整转发 **`/inspections/marking` 与 `/api/v1/inspections/marking`**，不剥掉前缀，保留查询、Cookie、原始 Host 和请求正文；设置 `X-Forwarded-For`、`X-Forwarded-Proto`。请求体上限至少 202MB，代理读取超时建议 200 秒，以覆盖图片导入与模型请求。不要将本机 1234 模型端口直接给平板使用。

普通试用账号 `admin / admin123` **只允许服务器本机直接登录**。经过反向代理的请求不能冒充本机；录入员可以先在业务电脑直接打开本机地址维护标准。如果确实需要其他电脑共同录入，需由 IT 配置已有的 `SV_ADMIN_USERS_FILE` 临时人员授权，记录独立操作人；配置格式在 `next/server/admin/auth.ts`，口令存 scrypt 哈希，文件须在代码仓库之外。企业 IDaaS 待对接，不把默认试用账号作为多人正式账号。

## 6. 原有正品与检测数据迁移

**Git 只包含代码、模板和明确标注的生成样例，不包含你录入的正品、检验照片、检测记录或私有配置。**

在原电脑停止业务服务，确认没有识别或导入正在执行，然后完整复制实际 `SV_NEXT_STATE_DIR` 目录。默认源目录为：

```text
outputs/next-state/
  inspection.sqlite        # 标准、版本、任务、检测轮次、人工修正、审计等
  inspection.sqlite-wal    # 如存在也一并复制
  inspection.sqlite-shm    # 如存在也一并复制
  files/                   # 正品原图、缩略图、检验原图、定位图及裁片
  reports/                 # 已生成报告（如存在）
  vision-records/          # 定位及模型原始记录（如存在）
  vision-traces/           # 调试留档（如存在）
  ...                      # 其余状态文件也一起复制
```

先保留一份独立备份，再将完整副本放到目标电脑的状态目录。不要只拷数据库，不要覆盖目标电脑已有业务资料。目标机器修改配置中的 Python、数据目录和 VLM 地址，再启动。迁移后仍可读取记录中的旧图片引用，但不会重新开放旧 HTTP 路由；历史快照和判断不修改。较早导出的 Markdown 如含旧链接，请在系统中重新下载报告。

不要复制 `.venv`、`node_modules`、LM Studio 模型权重或整个开发电脑用户目录。配置按公司环境重新填，私有照片经公司允许的方式传输。原电脑和目标电脑不能把同一个活动数据库目录放在共享盘同时运行；备份副本使用本地磁盘。

如果希望公司从空库开始，不复制状态目录即可；系统启动后管理员重新录入标准。内置生成样例仍会作为明确标注的演示任务出现，不代表真实来料。

## 7. 交给现场前跑一遍

1. 健康接口正常，启用的 VLM 名称与公司配置一致。
2. 在服务器本机登录管理员，核对迁移后的标准数量，打开几张原图和说明；或先新增一条实际标准。
3. 平板打开自主检测，输入物料编号、确认供应商，能看到相应正品。
4. 上传一张清晰单件照片，完成真实检测。单件能跑通后再试双件和较差光照；不把生成样例当现场准确率证据。
5. 确认结论、不良数、原图和报告；自主检测 MES 按钮始终禁用。完成后刷新和重启服务，记录仍可找到。
6. 检查照片模糊或模型不可用时，页面提示重拍／重试，不能把未完成结果当成合格。

自动检查可额外运行 `npm run test:next`，以及用上文配置的 Python 执行 `next/tests/local_preprocessing_test.py`。该 Node 测试部分用固定 HTTP 响应验证协议，不等于真实公司模型验收。`probe:next:real` 是开发电脑的 LM Studio 探针，不作为 Windows 或公司服务器通用部署命令。

## 8. 常见故障、更新和回退

| 现象 | 处理 |
| --- | --- |
| 页面 404 | 使用新的完整路径；核对反代保留前缀，不使用旧书签 |
| 平板打不开、电脑可以 | 核对 IP、主机绑定、端口、防火墙和无线隔离；电脑不要休眠 |
| 管理员在其他设备或反代登录被拒 | 本机试用的预期行为；直接在服务器登录，或按授权配置临时人员 |
| 上传或导入 413 | 检查服务单图 20MB／批量 200MB 限制及代理请求体上限 |
| 识别时报 Python 环境错误 | 检查 `SV_VISION_PYTHON`、虚拟环境依赖和运行权限 |
| 模型 401/404/超时/Schema 错误 | 核对 VLM 地址、模型名、认证、网络及 Schema；不要改成自动假结果 |
| 提示资源压力 | 释放内存，错峰运行；默认串行，不通过并行加压解决 |
| 查不到正品 | 确认使用正确数据目录，标准已启用且物料／供应商正确 |

更新前记录 `git rev-parse HEAD` 并备份整个状态目录。停止服务后，在无本地改动的部署目录执行 `git pull --ff-only`、`npm ci --include=dev`、按 requirements 更新 Python、重新构建和启动。若有本地修改先保留，不使用强制覆盖。应用回退应切回记录的 Git 提交，并使用匹配的**备份副本**验证，不能拿旧程序直接覆盖或降级活动数据库。

每次批量录入后和更新前备份，定期试恢复。长期运行的服务托管、备份轮换、HTTPS、监控和企业认证由后续正式部署阶段完善，本说明先保证试用可安装、可核验、可搬迁。

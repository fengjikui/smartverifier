# 客户端形态与服务架构建议

> 日期：2026-10-17
>
> 状态：H5与独立业务API方向已用于阶段一；目前以React/Vite、Node.js 24和SQLite跑通本地流程，识别、认证和MES仍为模拟适配。尚未进行目标平板或WeLink实机验证。

## 一、建议采用的方向

首轮继续采用平板浏览器 H5，后台提供独立业务 API。后续根据实机拍摄效果和公司入口要求，接入 WeLink H5 轻应用，或增加鸿蒙混合／原生客户端。

这是基于当前任务型交互、服务端模型识别、集中维护正品库及 MES 对接的工程建议。现阶段主要在打磨业务流程，网页便于在开发电脑与平板上持续试用；是否需要原生相机能力，应在拿到设备后用实际照片决定。

浏览器和原生应用都可以连接同一个业务后台。迁移时是否能保持后台不变，取决于我们是否把检测规则、任务状态、报告和 MES 回填放在服务端，而不是写成仅能在某个客户端运行的逻辑。

## 二、几种客户端形态的区别

| 形态 | 适合当前项目的用法 | 预计可复用部分 | 需要新增或适配的部分 |
| --- | --- | --- | --- |
| 浏览器 H5 | 首轮开发与目标平板试用 | 当前网页界面、公共后台与数据 | 浏览器拍照、相册、权限与输入体验的实机适配 |
| WeLink H5 轻应用 | 从公司 WeLink 打开现有网页 | 大部分网页与后台业务 | 入口配置、容器内行为、身份映射与需要的 JSAPI |
| 鸿蒙混合应用 | 用应用壳承载网页，必要时使用原生设备能力 | 大部分网页与后台业务 | ArkWeb 容器、网页与原生桥接、相机及权限适配、安装维护 |
| 鸿蒙完整原生应用 | 经过验证后需要更深的设备集成或特定原生交互 | 后台业务、数据与接口合同 | 用原生技术实现页面和终端能力；现有网页不会自动转换为原生界面 |
| We码小程序 | 公司明确要求小程序形态时评估 | 后台业务与接口，部分前端业务逻辑视框架而定 | 小程序组件、生命周期、平台 API 与身份适配，不能默认整套网页原样运行 |

WeLink 官方区分了 We码小程序与 H5 轻应用，后者可以接入已有 Web 页面。因此「在 WeLink 使用」不必一开始就等同于重做小程序。[华为云 WeLink 开发指引](https://support.huaweicloud.com/devg-welink/start.html)

鸿蒙 ArkWeb 提供在应用中加载网页的 Web 组件，支持应用集成 Web 页面。这为混合应用提供了官方能力基础，但容器权限、页面兼容与桥接仍需实现和测试。[华为 ArkWeb 文档](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-arkweb-194)

上表的改造范围是针对本项目的工程判断，不是官方对迁移工作量的承诺。目标 HarmonyOS 5 平板上的公司 WeLink 版本及所需能力，仍需实机核实。

## 三、后端哪些部分应保持独立

建议先按模块清晰的单个业务服务组织，识别工作交给受控后台任务执行。必要时再将图像处理或模型工作进程独立部署，不要求首轮拆成多个业务服务。

| 后端模块 | 负责内容 | 换客户端后的处理 |
| --- | --- | --- |
| 身份与权限适配 | 验证身份来源，统一为可信人员标识与权限 | 增加相应登录适配，核心任务规则复用 |
| 正品库 | 物料＋供应商关联、图片与说明、管理员维护 | 复用 |
| 任务与检测轮次 | 照片、元件、分次识别、补拍替换、提交门槛、历史与当前有效结果 | 复用，客户端只调用操作接口 |
| 图像与模型处理 | 定位、裁剪、摆正、质量反馈、提示依据、结构化结果与进度 | 复用，不要求每个客户端实现一套 |
| 人工核对与报告 | AI 原判、人工修正、修改原因、现场说明与冲突披露、汇总报告 | 复用业务规则；客户端各自展示 |
| 内部核验与维护审计 | 人工修正标记、置信度、样本筛选与批次核验、正品维护日志及管理员权限 | 集中复用，不要求每个终端重建记录 |
| MES 集成 | 任务读取、身份传递、结果与附件回填、幂等与保存回执核实 | 集中复用，不让各客户端分别对接 MES |
| 记录与文件存储 | 任务记录、原图与衍生图、报告、操作追溯 | 复用；图片按文件引用管理，不绑定浏览器临时地址 |

后端决定「是否允许提交」「不良数是多少」「哪一轮是当前有效结果」。客户端只隐藏按钮不足以落实业务规则，换成原生或 WeLink 后也必须经过同一服务端校验。

人工复核是可选能力，不是逐件人工确认的正常通道；有明确结果的低置信度仅提示关注。内部核验、模型置信度与白名单设计见[复核与持续改进设计](检测复核与持续改进设计.md)。

关系型记录存储与图片／报告文件分开组织。具体数据库、Web 框架和工作队列产品留到服务架构细化时选择；本建议尚未决定这些产品。

## 四、客户端需要隔离的终端能力

将拍照、相册选择、登录入口、语音补充及文件打开等能力集中在终端适配层。网页业务页面通过统一接口调用，不到处直接依赖浏览器或 WeLink 全局对象。

同样的「拍一张照片」操作，在浏览器、鸿蒙原生或 WeLink 中可使用不同实现，最终都上传图像并得到相同的业务图片标识。后端不依赖某个设备的文件路径或本地 URI。

服务端处理任务通过任务标识查询进度，页面退出后后台状态仍可恢复；不能把识别流程是否完成只保存在一个页面组件中。跨人员草稿是否可共享仍按 BIZ-02 后续确认。

## 五、迁移时后台仍可能需要调整什么

核心业务大部分可复用，不代表任何情况下后端都零修改。常见调整位置包括：

- 新客户端的登录回调、凭证校验、会话与人员身份映射。
- 终端上传行为差异、重试方式、文件打开或下载适配。
- 新增功能确实改变了数据含义时，例如多面拍摄或离线采集同步。
- WeLink 容器要求的接口签名、应用配置或新增服务端适配。

WeLink 的免登流程解决获取平台身份、映射业务用户的问题，不能据此推断该身份已经取得 MES 的访问权限。当前公司 IDaaS 与 MES 信任约定仍是正式对接依据；未来 WeLink 身份如何接入，需要共同确认。[WeLink H5 轻应用免登说明](https://open.welink.huaweicloud.com/wecode/docs/dev/serverapi/authentication/standerH5.html?v=1547690387)

## 六、先验证拍摄能力，再决定是否增加原生端

浏览器获取相机实时流的 `getUserMedia()` 需要安全上下文，通常应通过 HTTPS 提供平板访问。电脑上的 localhost 例外不能直接推广到平板访问局域网 HTTP 地址的情况；相册选图或系统拍摄入口也需要各自实测。[MDN：getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

原生相机框架提供分辨率、焦距、旋转等控制能力，但具体能力也受设备支持影响。是否需要采用它，应比较实际拍摄质量和操作效果，而不是假定换成原生就一定识别更准。[华为相机拍照文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-v5/native-camera-shooting-V5)

拿到目标平板后，先验证清晰度、连续拍摄、相册添加、补拍、语音输入、弱网恢复和报告查看。如果浏览器方案满足要求，就继续完善；若关键设备能力受限，再评估增加鸿蒙混合应用或完整原生客户端。

无论采用哪种客户端，目前的模型识别仍依赖服务端。原生端支持本地缓存，不等于当前方案已经具备离线 AI 检测或离线 MES 回填。

## 七、下一阶段的交付建议

1. 完成并评审[PRD 草案](产品需求文档-PRD-v0.1.md)。
2. 设计完整平板操作流程与界面原型；新增个人历史功能另开讨论，不把删除规则直接写死。
3. 细化客户端 API、数据关系、检测轮次与回填状态，再搭建首轮服务。
4. 首轮把浏览器流程跑通，保留终端适配边界，后续按实测结果接入其他客户端。

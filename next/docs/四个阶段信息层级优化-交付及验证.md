日期：2026-10-18。适用于 `next/web`，延续用户确认的信息主次原则。

同日后续澄清：用户希望保留标题与查询左右并排的布局，加强的是表格内部的表头。当前为表头增加底色、较深字色、适中字重和上下留白，垂直居中；「操作」列标题与操作按钮居中对齐。上一轮恢复全宽查询的尝试已撤回，旧截图仅作历史记录。

此修订已通过类型检查、生产构建和横竖屏浏览器检查，截图为 `task-table-header-landscape.png`、`task-table-header-portrait.png`。

## 本轮交互

| 阶段 | 优先信息与动作 | 次要信息处理 |
| --- | --- | --- |
| 任务选择 | 任务、物料供应商、当前状态和搜索 | 保留标题与搜索并排布局，加强表头视觉与上下留白，试用说明放在底部折叠，移除重复的人员及 MES 底栏说明 |
| 照片总览 | 照片、检测状态、异常筛选和底部下一步 | 报告／本次说明／样例归入「更多」；替换和移除放入每张照片的菜单 |
| 检测中 | 已定位元件数、已完成数、进度和每张状态 | 过程说明保持一行；禁止重复检测、修改照片和提前提交，已生成结果仍可查看 |
| 提交结果 | 成功或失败、检验单号、结论、不良数和下一步 | 保存回执、人员和时间折叠在「查看保存凭证」；失败原因及重试入口直接显示 |

普通流程保持「选任务 → 添加照片 → 开始检测 → 提交到模拟MES」。没有新增强制人工复核或额外确认步骤。照片较多时继续支持紧凑预览；检验员仍可分次补拍。

检测进度使用后台返回的实际已定位元件数和已完成数；尚在定位时显示不定进度，不填假百分比。多张照片逐步定位时，已定位总数可能增加，因此它不是预先约定的应检样本数，也不承诺剩余时间。

照片需重拍或未生成结论时，醒目提醒保持展开，可直接筛出「需处理」照片；仅剩重拍内容时，主按钮引导查看重拍照片，不能提交。替换后保留照片序号，不重复统计。提交失败时明确保留本轮结果，重检失败不覆盖上次成功结果。

横屏 1280×840 底栏并列状态和操作；竖屏 840×1280 底栏将状态与按钮分两行，保证拍照、相册和检测／提交按钮完整显示。任务列表、菜单和凭证均可用触控或鼠标操作，辅助入口保持至少 44 CSS px，菜单项至少 48 CSS px。

## 实现与限制

页面拆为 `task-selection.tsx`、`inspection-overview.tsx`、`inspection-transfer.tsx`，共用 `action-menu.tsx`；App 保留上传、路由和服务交互。未更改服务端统计、历史保护或回填协议。

仍使用模拟身份、内置样例识别与模拟 MES；没有运行真实模型，也没有宣称完成目标华为平板真机拍摄或公司接口验收。本次通过样例入口添加照片，系统相机／相册的真机权限与成像能力仍需实机测试。

隔离浏览器测试应使用与正式试用不同的主机名（例如测试用 `localhost`，正式试用用 `127.0.0.1`），避免相同主机不同端口共享会话 Cookie。临时服务、页面和数据在完成后清理，保留截图及验证记录。

## 二、怎样回复最省事

- 可以只答一项，也可以一次答多项，不必全部答完。
- 已确认的问题不用重新回答，除非你希望改变之前的结论。
- 未掌握的信息可以写「待问业务」「待问 MES」「设备到了再试」。
- 设计细节可以写「按你的建议」「由你设计」，助手记录默认方案，后续用原型或实际试用复盘。
- 可以直接在聊天中回复编号；由助手更新文档，你不必手动维护几个文件。

回复示例：

```text
P01：采用建议方案。
P02：还有一个功能想讨论：……；希望第二轮再做。
MES-04：需要问 MES 同事。
```

## 三、当前重点问题与答复进展

### P01 · 有未处理照片时，是否可以提交部分结果

- 状态：已确认，对应整体方案 D7，不需要重新回答。
- 场景：一个任务里已有部分元件得到结论，另有照片待重拍、识别失败或尚未识别，检验员希望点击「提交结果」。
- 原问题：必须先处理这些照片，还是可以直接只提交已经完成的部分？
- 当前答复：按建议执行，核心原则是**不允许直接部分提交**。本轮已拍、纳入检测而尚未识别出明确结论或需要重拍的内容，未处理完就不能进入提交阶段。
- 与最新复核要求的关系：已有明确有效结论、只是标记低置信度或建议复核时，不强制人工确认；实际无法判断、未处理或结果未更新仍阻止提交。
- 既有删除／替换能力保留：拍错或不合适照片由检验员明确处理，系统不得自动隐藏失败项、只提交成功项，也不能把删除视为合格。
- 后续核实：用户会与业务方确认是否存在应检样本数规定；若有，再明确来源与数量校验口径，见 BIZ-04。当前不增加固定数量门槛。

### P02 · 后续新增功能与首轮范围

- 状态：持续收集，不要求现在一次想全。
- 已知：当前方案描述的是正常使用主流程；用户后续还会提出改善使用体验的新功能。
- 问题：现在是否已有必须影响首轮流程的新功能？如果有，请描述「使用者在什么情况下，希望做什么」。暂时没有就先推进主流程。
- 处理方式：新功能先登记，再判断属于首轮必需、下一轮增强或暂存想法；不把尚未提出的功能默认纳入开发范围。
- 当前答复：已提出个人过往检验记录查看，可能按天组织；历史维护与能否手动删除需专门讨论。已记入 IDEA-01／02，未默认开放删除权限。
- 后续补充：人工修正记录留痕与检索、置信度提示、正品维护审计已进入基础设计；可选自动回填、改判案例主动批次发送已登记为 IDEA-03／04，具体规则后续设计。

不需要在需求讨论中由你先选定 OpenCV、某个检测模型、数据库或前端框架。助手会结合验证结果选择，并解释影响使用和部署的取舍。

## 七、需要设备和样本验证的事项

| 编号 | 验证内容 | 怎样得到结论 |
| --- | --- | --- |
| V01 | 单张拍 1／4／6／8 个元件的清晰度与操作方便程度。 | 收到目标平板后实拍，不用屏幕像素参数推算拍摄效果。 |
| V02 | 元件定位是否漏掉、误框，裁剪是否完整，旋转是否有助于识别。 | 用真实摆放、背景、方向、大小不同的照片验证，保存原图与结果对照。 |
| V03 | 合格、不合格、允许变化、现场补充说明与置信度提示是否合理。 | 人工核验原判与改判，覆盖高分错误、低分正确和未修改样本；调整规则与阈值。 |
| V04 | 目标浏览器拍照、相册、连续添加、语音输入和中途恢复是否顺手。 | 目标平板实际走完整流程，电脑浏览器试用不替代实机验证。 |
| V05 | 模型等待时间、排队、多用户使用和电脑负载。 | 先记录单任务实测，再按试用规模逐步验证；遵守本机低并发与热状态检查要求。 |
| V06 | 真实 MES 的附件查看、保存回执、重试和重新检测更新。 | 完成接口联调后实际核对，不用模拟回填成功代替真实验证。 |

不预先编造准确率或承诺实拍上限。验证时记录样本、预期结果、实际结果及问题，再一起确定可接受的首轮效果。

## 八、后续新功能需求池

当前主流程是第一阶段基础，后面可以继续增加方便使用的功能。你不需要现在一次性把所有想法说完。

每个新增想法按下面几项简单记录即可：

- 希望增加什么功能。
- 谁在什么情况下会用，想省掉哪一步或解决什么问题。
- 是首轮必须、下一轮增强，还是先留作想法。
- 是否会改变当前流程、报告内容或 MES 接口。

| 编号 | 功能与使用场景 | 阶段 | 状态 |
| --- | --- | --- | --- |
| IDEA-01 | 查看自己过往的检验记录，可能按天组织。 | 待专门讨论 | 用户已提出；入口、筛选、日期口径和阶段尚未细化 |
| IDEA-02 | 历史记录维护及能否由检验员手动删除。 | 待专门讨论 | 用户已提出；删除对象、权限和追溯关系未定，尚未开放删除已提交历史 |
| IDEA-03 | 可选「检测完毕自动回填」。 | 用户提出后期能力 | 需明确本轮采集结束信号、开关范围、适用条件；不提交整张检验单，保留 P01 |
| IDEA-04 | 人工修正案例分批主动发送给维护人员。 | 发送方式待设计 | 留痕检索纳入基础设计；发送渠道、对象和时机未定，不自动发送 |

已有的分次补拍、人工改判、现场说明和重检属于已定基础能力，不重复放入「未来可选」而延后。

置信度输出与提示、人工修正额外标记和后台检索、正品操作日志也作为基础数据与功能设计，不能等到做主动推送时才开始采集记录。

## 九、建议的实施顺序

1. **收束首轮需求。** P01 已确认；个人历史记录方向已登记并计划专门讨论；现已形成 PRD 草案，后续明确阶段范围。
2. **设计完整操作流程与可看的原型。** 覆盖登录、任务选择、拍摄与补拍、识别进度、结果总览、元件详情、人工修正、回填状态，以及独立的正品管理。你看原型、提反馈，再定首轮界面。
3. **确定数据和接口组织。** 区分任务、检测轮次、照片、元件、AI 原判、人工结论、检测说明及 MES 回填记录；落实旧有效结果与新一轮结果的边界。正式接口未知部分隔离处理。
4. **实现一个完整的本地闭环。** 使用可区分的模拟任务与 MES 服务，接入图像处理和模型，跑通拍照到报告与模拟回填。旧数据不混入新版试用数据。
5. **边试用边完善。** 补拍、替换、提示词修改、人工修正、重检、失败恢复分别实际试用；助手先动手测试交付物，再交给用户体验。
6. **接入 IDaaS 与真实 MES。** 根据外部清单完成认证、任务读取、结果和附件回填、重复请求与更新验证，明确标记真实连接状态。
7. **目标平板与公司电脑试用。** 用真实元件完成拍摄、识别、复核、报告和 MES 核对，按问题迭代；再安排下一轮便利功能。

各阶段可以逐步推进和试用，不要求一次完成全部页面、数据库和接口。阶段一已实现本地流程并完成自测，具体范围见[阶段一交付与验证记录](阶段一交付与验证记录.md)；模型和公司接口后续接入。

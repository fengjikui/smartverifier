# 统一路径与扩展约定

2026-10-18。丝印检测作为一种检测类型，公共路径命名为 `marking`。此轮只调整地址组织，检测规则、业务数据、模型配置和权限不变。

## 当前入口

| 用途 | 路径 |
| --- | --- |
| 检验工作台（默认自主检测） | `/inspections/marking` |
| 模拟 MES 任务 | `/inspections/marking?entry=tasks` |
| 平板模拟器 | `/inspections/marking/preview/tablet` |
| 正品管理 | `/inspections/marking/admin/standards` |
| 新增正品 | `/inspections/marking/admin/standards/new` |
| 正品详情／编辑／复制 | `/inspections/marking/admin/standards/{id}`、`/{id}/edit`、`/{id}/copy` |
| 正品回收站 | `/inspections/marking/admin/standards/trash` |
| 批量导入 | `/inspections/marking/admin/imports` |
| 维护日志 | `/inspections/marking/admin/audit-logs` |
| 只读任务列表 | `/inspections/marking/admin/tasks` |
| 本机模型调试 | `/inspections/marking/debug/model` |

接口统一使用 `/api/v1/inspections/marking` 前缀，主要资源为：

- `GET /standards`：检验员选择正品。
- `GET /tasks`：查询模拟任务；`/tasks/{id}/open` 等沿用原动作。
- `GET/POST /checks`：最近自主检测／开始自主检测。
- `/rounds/{id}/...`：照片、检测、人工修正、完成及报告等。
- `/admin/standards`、`/admin/imports`、`/admin/audit-logs`：管理接口。
- `/session` 与 `/admin/session`：沿用检验与管理鉴权，未改变身份模式。

静态资源位于 `/inspections/marking/assets/...`，业务图片和报告使用上述 API 前缀。统一常量与兼容映射集中在 `next/shared/paths.ts`。

## 兼容与部署

旧网页入口（包括 `/admin/new`、`/tablet-preview`）通过同源 308 跳转到新地址，保留检测记录、样例、报告等查询参数。旧 API 的 GET 请求和旧静态资源也跳转；旧 API 的写请求直接兼容处理，避免重新发送上传正文。

历史记录里的图片地址不批量修改，也不改写标准版本或审计。对外返回和新导出报告中的图片链接使用新前缀；描述和模型原始文本不做替换。旧会话仍有效，已有书签可继续使用。

公司反向代理需将网页 `/inspections/marking` 和接口 `/api/v1/inspections/marking` 转发至同一服务，保留路径、查询、请求正文及 Cookie；两者保持同源，不剥掉前缀。兼容旧书签时，也需将旧入口转发到本服务执行跳转。

## 后续扩展原则

未来其他类型可使用 `/inspections/{type}` 和 `/api/v1/inspections/{type}`，与 `marking` 并列。当前不预建其他类型的页面、数据库或插件机制；总门户、统一身份等按实际需求设计。API 的 `v1` 表示对外契约版本，与模型或正品标准版本相互独立。

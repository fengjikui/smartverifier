# 模型调试窗口与耗时口径

日期：2026-10-18。用途：在服务器本机检查实际模型调用，不属于检验员日常操作页面。

VLM配置现已统一，支持本机SDK和公司兼容HTTP，见[VLM服务配置与迁移](VLM服务配置与迁移.md)。HTTP模式首token为客户端首次观察，速率由用量和墙钟估算，不冒充SDK或后端纯解码统计；上游未返回的token数显示“未记录”。下面原实验的SDK数据及历史口径保留。

## 打开和试用

1. 使用 `npm run start:next:real`，打开 <http://127.0.0.1:5190/debug/model>。现有本地试用会话可直接使用；未登录时点击「进入调试窗口」。
2. 左侧选择历史调用，查看实际发送的正品图、待检图／白板、完整提示词、模型原文与SDK统计。点击图片打开原始PNG，展开SHA256可以核对字节。
3. 选「单件／4件／6件」、输入顺序与输出约束，点击「发送内置样例」。默认「固定规则与正品图优先＋JSON Schema」，可切回旧顺序与提示词JSON作对照。这些样例只调用模型，不创建、修改或提交检验任务。单件是正品图自身的链路对照，并非独立样本。
4. 新调用会实时展示片段和各元件输出完整的时刻。工作台中的真实识别也会自动留档，可以在本窗口查看。复制保留模型原文；「格式化显示」仅改变显示。导出JSON包含事件和图片索引、哈希，图片可另行点开保存。

页面按400ms轮询当前记录，按1.2秒刷新调用列表。时间戳在Python SDK接到事件时记录，**不会把网页轮询时间当成生成时间**。关闭页面不取消正在进行的调用，重新打开可查看落盘结果。

## 各时间点含义

| 指标 | 起点／含义 |
| --- | --- |
| 输入快照起点 | 开始保存本次实际发送的输入。此前的拍照、上传到业务服务、定位裁剪、调用方PNG编码不在此时钟内 |
| 图片准备完成 | SDK完成本次图片句柄准备；不代表模型完成视觉编码 |
| 首token（SDK事件） | SDK的首次token回调到达；与SDK最终统计的起算范围不同 |
| 首段正文 | 首个非推理、非空的流片段到达；若有代码围栏，围栏也属于输出文本 |
| 元件JSON完整 | 根对象`items`数组中的一个完整对象到达，支持嵌套、字符串转义及任意字段顺序 |
| 从输入起 | 元件JSON完整的累计时间 |
| 从首段正文起 | 首段正文到本件对象输出完毕的累计时间 |
| 本件输出区间 | 首件从首段正文计算；后续从上一件对象结束计算。包含间隔符，不是独立视觉计算时间 |
| 生成结束 | SDK取得完整生成结果与统计 |
| 整批校验结束 | 生成结束、子进程返回后，服务完成JSON结构及ID集合校验。还可能有业务层质量／置信度检查 |
| SDK首token等待 | LM Studio报告的`timeToFirstTokenSec`，不是浏览器计时，也不是单独的思考时间 |

模型内部视觉编码、预填充及后端调度没有独立的可靠计时，不能把首token等待全部称为图像识别或思考。多个对象若在同一个SDK片段中到达，可以有相同时间。部分对象到达后只作观测，不提前写回MES；仍按整批完整校验和原有提交规则处理。

## JSON约束与识别正确性

原工作台和EXP-007采用**提示词要求JSON＋返回后严格校验**，不是生成时Schema约束。解析器只允许整个回答被一层代码围栏包裹，不搜索损坏片段、不补字符、不按数组顺序猜编号。

2026-10-18 的 EXP-008 起，真实检验主流程及调试样例默认通过Python SDK `response_format`实际传入Schema，并采用固定前缀输入。原始事件中可查看Schema；失败会明确保留错误，不偷偷退回提示词调用。提示词仍保留字段含义与结构示例，两者可以同时存在。

固定前缀按四条消息构造：`system固定规则与标准说明 → user正品图 → assistant固定协议确认语 → user现场说明、动态编号与待检图`。确认语只是分隔消息，未伪造读取正品后的判定。这样绕开SDK合并连续用户消息、运行时把同一消息中的图片提前的行为；最后一条里的图片仍可能排在动态文字前。调试页「请求参数、消息顺序与Schema」展示传输前的消息和实际约束参数，不冒充模型最终token序列。

**固定前缀不等于必然命中缓存。** 当前模型与运行时的换图对照、原样重复探针和限制见[EXP-008报告](../research/prefix-cache/README.md)。

[LM Studio官方SDK说明](https://lmstudio.ai/docs/python/llm-prediction/structured-response)提供此参数；其[结构化输出说明](https://lmstudio.ai/docs/developer/openai-compat/structured-output)区分GGUF与MLX后端实现。当前实测只代表本机这套模型和运行时，不代替未来服务器的兼容验证。

Schema约束字段、类型、枚举及本次元件数组长度，仍需后置校验重复／漏项、`status`与`verdict`关系。它不会保证OCR正确、结论正确，或保证自由文本一定指出规则冲突。也不会自动把提示词里的每条要求翻译成约束：本次试验提示词要求`features`最多1条，Schema没有限制这项长度，模型实际输出了2条，结构校验仍可通过。这个差别在报告中保留，后续可把能表达的限制纳入Schema。

## 启停、数据与范围

- `start:next:real`默认启用本机调试；`SV_MODEL_DEBUG=0`可关闭。普通`start:next`默认不启用，手动启用为`SV_MODEL_DEBUG=1`。
- 正常识别默认`SV_VISION_INPUT_LAYOUT=prefix-first`、Schema开启。兼容对照可设置`SV_VISION_INPUT_LAYOUT=legacy`、`SV_VISION_SCHEMA=0`后重启本系统服务；无需重启LM Studio。`/api/health`的`visionConfiguration`可核对生效配置。
- API要求本地试用会话，且只接受服务器回环地址。局域网平板不会获得调试图片／提示词访问；这不是公司管理员权限体系，生产部署应显式关闭或另接管理员授权。
- 记录位于当前`SV_NEXT_STATE_DIR/vision-traces/<调用UUID>/`，默认`outputs/next-state/vision-traces/`，属于Git忽略的运行数据。包含原始图像和提示词，没有自动上传外部平台；暂不自动清理，长期启用需另定保留周期与磁盘预算。
- 每个新请求保存实际发送PNG的字节、尺寸、SHA256、消息顺序、提示词、模型配置、片段、统计与错误。不是LM Studio内部视觉张量、完整渲染后token序列或隐含推理的可视化。
- 调试样例串行，识别忙时拒绝新调试请求；调试运行时也不允许新开正常识别。不会加载／卸载模型或抢占用户在LM Studio中主动发起的推理。
- 实际检验、调试和离线实验在推理前后检查可取得的CPU、内存、系统热／性能告警，限制数值库线程数。没有温度传感器读数，不声称具体温度。

# 本机真实识别试用与部署

平板工作台已接到真实VLM；本文介绍保留的本机LM Studio方式。公司兼容HTTP服务使用[VLM服务配置与迁移](VLM服务配置与迁移.md)，统一填写`SV_VLM_ENDPOINT`等配置。企业身份认证、任务列表和MES回填仍为模拟；真实正品库的管理接口尚未接入。

## 直接试用

1. 打开 `http://127.0.0.1:5190/tablet-preview?demo=real`。
2. 点击「进入本地试用」，进入「真实比对 · 双件 · 含字符差异」。
3. 点击「使用模拟拍摄照片 · 真实识别」，再点「开始检测」。这会实际调用本机模型，不使用预设判定。
4. 完成后点击照片，通过右上角编号切换元件，查看 `SV358` 与 `SV385` 的逐字差异。
5. 在详情点击「查看原始照片」，切换「原始照片／定位与编号／裁片白板」。编号在原图外侧，不盖住丝印。
6. 「更多 → 查看完整报告」可查看并下载 Markdown。提交按钮仍为「提交到模拟MES」。

任务列表另外提供单件、较暗光照三件的试用任务。也可从相册添加照片，但这些试用任务的标准固定为虚构的 `SV358 / A26 / 0147`，不适用于任意真实物料。现场物料需要先由管理员录入对应正品标准。

旧的「内置样例」继续用预设结果演示流程；与「模拟拍摄照片＋真实模型」明确区分。普通相册上传即使与旧样例字节相同，也不会按哈希替换成预设结论。

## 当前采用的方法

`原图保留 → EXIF方向纠正 → OpenCV定位 → 从全分辨率原图裁剪、几何转正 → 正品图＋单件裁片交给千问 → 校验JSON → 展示结果`

- OpenCV 使用绿色背景分离、轮廓和最小旋转矩形，不需要额外训练权重或显卡。CPU限制为2线程。
- 编号标注图、白板和模型输入分别保存；模型接收没有编号覆盖的裁片。
- 白板按原裁片像素排版，不缩小裁片；本阶段仅用于查看及留档，**尚未启用白板批量识别**。
- 早期提示词版本的本机27B测试每件约10～14秒；输入、输出约束或说明长度改变后需重测。两件、三件按顺序累加，并显示逐件进度。该数据不是服务器性能承诺。
- 找不到目标、严重模糊、出框、分离不可靠时要求重拍；模型不可用、超时或JSON无效时保留失败状态，不能部分提交。
- 新增照片只识别未完成部分；修改现场说明后复用裁片重新判断；新一轮重检生成独立的元件身份，旧记录保留。
- 模型默认先接收固定规则与正品图，再接收现场说明、动态编号与待检图；通过实际Schema参数约束输出，并继续校验编号完整性和业务关系。输入重排不保证本机换图缓存命中，参见[换图对照报告](../research/prefix-cache/README.md)。
- 置信度是模型自评，不是准确率；人工修正保留AI原判、人员和原因。

## 重新启动

先在 LM Studio 启用本地服务并加载视觉模型。本适配器**不会自动加载、卸载或修改共享模型配置**。

```bash
npm install
npm run build:next
npm run start:next:real
```

默认使用现有 `agent-tools/image-focus/.venv/bin/python`、`http://127.0.0.1:1234/v1`、已加载标识 `hr-qwen`，模板路径为用户目录下的 `.lmstudio/models/lmstudio-community/Qwen3.8-27B-MLX-4bit/chat_template.jinja`。

可在仓库根目录创建被Git忽略的 `.env.next.local`。`start:next:real` 会读取它；不要提交本机路径或凭证。

```dotenv
SV_VLM_PROVIDER=lmstudio
SV_VLM_MODEL=hr-qwen
SV_VLM_ENDPOINT=http://127.0.0.1:1234/v1
# 切换模型时，必须填写该模型自己的、支持enable_thinking的模板。
# SV_VLM_TEMPLATE=/absolute/path/to/chat_template.jinja
# SV_VISION_PYTHON=/absolute/path/to/python
SV_NEXT_PORT=5190
# 以下为默认值；对照旧方式可改为legacy与0。
SV_VISION_INPUT_LAYOUT=prefix-first
SV_VISION_SCHEMA=1
```

`npm run start:next` 默认仍为离线模拟模式。健康检查 `/api/health` 的 `recognition.mode` 用于区分两种模式；顶层 `mode:mock` 指企业系统集成仍为模拟。

## 独立安装视觉依赖

部署到另一台电脑时可以使用独立虚拟环境，无需复制本机环境：

```bash
uv venv next/.venv --python 3.12
uv pip install --python next/.venv/bin/python -r next/server/vision/requirements.txt
```

再设置 `SV_VISION_PYTHON`。Windows需改为该虚拟环境的 `Scripts/python.exe`。新版服务按Node.js 24部署，本轮验证使用24.14.0。LM Studio SDK固定1.5.0，与现有经过验证的传输器保持一致。当前逐请求关闭thinking使用Qwen模型自身模板，尚不是任意模型的通用适配器。

LM Studio SDK仅接受本机回环地址；公司模型使用服务端配置的HTTP兼容适配器，可填内网HTTP／HTTPS地址。浏览器始终通过业务服务调用模型，图像会发送至管理员所配置的VLM地址。其他非兼容协议仍需替换适配器。

## 验证及留档

```bash
npm run check:next
npm run test:next
agent-tools/image-focus/.venv/bin/python next/tests/local_preprocessing_test.py
npm run probe:next:real
npm run probe:next:real -- --override
```

最后两条会真实推理，需要LM Studio已加载模型，使用独立状态目录，不修改日常试用数据。一次只运行一个探针；运行前及每组之间检查内存、负载和系统热状态。可用内存不足8GiB或出现系统热／性能告警时暂停本次处理。无温度读数时不报告具体温度。

日常数据在 `outputs/next-state/`：原图及派生PNG在 `files/`，定位及模型原文在 `vision-records/`，SQLite保存任务、轮次和人工修正。原始模型响应附带发送尺寸、哈希、提示词版本、耗时及模板哈希；模型内部处理尺寸未知时记为null。服务未接收任意远程图片URL或用户提供的本机路径。

## 当前适用边界

绿色防静电垫、相互分离的黑色封装、完整入镜、每张最多6件是当前定位配置。实际验证为1／2／3件，4～6件还未取得实拍证据。遮挡粘连、绿色／透明／浅色封装、复杂托盘及强透视需要新数据和检测器。当前是矩形区域裁剪，不是像素级抠图；几何转正不保证文字180°方向，也不做生成式超分补字。

这次没有目标平板实拍、没有企业IDaaS/MES联调，也没有生产验收。详细证据见[本轮实验材料](../research/real-vision/README.md)。

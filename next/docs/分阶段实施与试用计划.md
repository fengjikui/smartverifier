# 分阶段实施与试用计划

> 2026-10-17。以已确认 PRD 与 Figma 为依据，每阶段先由助手测试，再交付用户试用。阶段一已完成本地试用版本；后续阶段结合用户反馈继续。

2026-10-18更新：阶段二的本机真实VLM、OpenCV及公司兼容HTTP适配已接入；真实来料与目标平板验收仍待完成。阶段三的IDaaS、MES和实际正品管理端未接通。当前停止性能优化，按[试用演示基线与缺口清单](试用演示基线与缺口清单.md)优先准备真实标准与演示环境；以下保留原阶段划分。

1. **阶段一：平板正常流程。** 新版独立 `next/web`、`next/server`、`next/shared`。真实上传原图、服务端草稿、元件计数、增量检测、可选改判、逐字对照报告、模拟回填、重试及重检。内置虚构样例使用预设结果，真实上传图不生成伪造判定。认证、MES 与识别均明确标为模拟。
2. **阶段二：真实图像与模型。** 接入元件定位、裁剪、旋转、质量判断和当前千问服务，复用第一阶段的任务与结果接口。用真实样本核验准确性、失败恢复、等待反馈和本机负载。
3. **阶段三：公司系统接入。** 根据 AUTH／MES 对接资料替换认证、任务和回填适配器，核验身份、附件、保存回执和幂等；完成管理端实际维护能力。
4. **阶段四：真机与公司现场。** 在目标华为平板和公司电脑验证拍摄、连续添加、视口、触控、网络、模型与MES全链路。按实际反馈调整；新增历史记录等功能另行确认。

阶段一首选 React＋Vite，复用仓库已有 Button／Input／Dialog，使用独立主题样式。服务端采用本机现有 Node 24 与 SQLite，业务规则在服务端集中执行，图片和报告单独存储。第一阶段不引入额外模型或同时启动高负载推理。

首轮视口基准为 Figma 的 1280×840，验证 1280×800、1024×768、横竖切换及窄屏；使用实际 CSS 可视高度与安全区。电脑模拟不替代目标华为设备验证。

每阶段交付包含启动方式、可访问地址、验证记录和仍未接通的能力；未达到验收的能力不写成已完成。
